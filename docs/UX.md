# UX: экраны и потоки (MVP)

Статус: черновик на ревью · 2026-10-01. Термины — в [SPEC.md §2](SPEC.md#2-глоссарий).

## 1. Карта экранов

Два режима: **калькулятор** (каждый день: открыл — блюдо уже выбрано или в один тап на полке, ввёл готовый вес — видишь, сколько класть каждому) и **настройка** (блюдо, компании, тара — редко, с явным «Создать» / «Сохранить»). Калькулятор устроен как конвертер величин (SPEC §3б). С этапа 15 нет нижнего меню, готовок и истории.

```
┌──────────────────────────────────────┐  «⋯» → Изменить «Гречка» → Редактор #/d/<id>/edit
│ 🔍 (Гречка) Макароны Рис …         ⋯ │  «⋯» → Добавить блюдо     → Редактор #/d/new
├──────────────────────────────────────┤  «⋯» → Настройки          → #/settings
│ Калькулятор #/d/<id>  (главный, #/ → │  🔍, ⌘K, «/» → Меню блюд #/dishes: поиск, тип, сортировка,
│ последнее блюдо)                     │       свои блюда и популярные с весом («⋯»: Добавить блюдо)
│ Сухой 70 г | Готовый 186 г           │
│ Кто ест · полоса долей · люди        │  Без блюд #/ — «Пока нет блюд»: «Блюдо», «Популярные блюда»
│ (клавиатура — системная, по тапу)    │  Аккаунт #/account · ссылка-приглашение → Вступить #/join/<код>
└──────────────────────────────────────┘
```

Экраны поверх другого (§3а) — его адрес плюс шаг: тара ▾ «Добавить тару» → «Новая тара» `#/d/<id>/tare/new`; «Кто ест ▾» «Добавить компанию» → «Новая компания» `#/d/<id>/company/new`; «Из простого блюда» в редакторе → `…/edit/from-dish` (у нового блюда `#/d/new/from-dish`); копирование без доступа к буферу → «Скопируйте вручную» `…/copy` (калькулятор, Настройки → «Группа»); Настройки → «Группа» → «Вступить по коду» → `#/join`.

**Шапки.** На калькуляторе — полка блюд (🔍 «Найти блюдо» в начале вне прокрутки, чипы по последнему использованию, «⋯» справа). На остальных экранах — «← назад», заголовок и «⋯» с действиями экрана и «Настройками» (везде одно меню). Точка «нужно внимание» (синхронизация) — на «⋯» и на пункте «Настройки».

**«Назад».** «←» в шапке и «Отмена» возвращают на экран, с которого открыли этот, с теми же параметрами (то же блюдо, тот же подраздел настроек, прокрутка): это шаг назад по истории, ровно как системный «назад» (кнопка браузера, свайп от края на iPhone), и новых записей в истории он не добавляет. Примеры: калькулятор «Гречки» → «⋯» → «Добавить блюдо» → «←» — снова калькулятор «Гречки»; «Изменить блюдо» → «Составное на основе» → «←» — форма простого блюда → «←» — калькулятор; «Настройки», открытые с любого экрана, — назад на него; «Аккаунт» — туда, откуда открыли («Настройки», строка синхронизации, «Вступить в группу»). Подпись у «←» (с `sm`, на телефоне только стрелка) — «Назад». Если предыдущего экрана в приложении нет (открыли по прямой ссылке), «←» ведёт на запасной экран, заменяя текущий в истории, и подписан его названием:

| Экран | Запасной «назад» |
|---|---|
| Меню блюд, «Настройки», «Вступить в группу» | калькулятор (`#/`) |
| «Новая тара», «Новая компания» | калькулятор этого блюда |
| «Из простого блюда» | форма блюда |
| «Скопируйте вручную» | экран, с которого копировали |
| «Вступить по коду» | «Настройки» → «Группа» |
| подраздел настроек (телефон) | список «Настроек» |
| «Добавить блюдо» | меню блюд |
| «Изменить блюдо» | калькулятор этого блюда |
| «Аккаунт» | «Настройки» → «Аккаунт» |
| «Новый пароль» | «Аккаунт» |

После «Создать» / «Сохранить» форма заменяется калькулятором блюда, после удаления блюда — калькулятором (`#/`): «назад» на форму не возвращает.

**Переходы между экранами.** Новый экран въезжает коротко (200 мс): из прозрачного и сдвинутого на 24 px. Вглубь (калькулятор → форма, «Настройки» → подраздел, калькулятор → меню блюд (🔍, ⌘K, «/») → блюдо) — справа налево; назад («←», «Отмена», системный «назад» в браузере и на Android, свайп от края на iPhone; «вперёд» в браузере выглядит так же) — слева направо. Уходящий экран не анимируется, шапка едет вместе с экраном. Без анимации: при открытии и перезагрузке страницы, при замене адреса (после «Создать» / «Сохранить» / удаления, запасной «назад» без предыдущего экрана, переключение подразделов «Настроек» с `md`) и при «уменьшить движение». Во время перехода нет горизонтальной прокрутки; ввод он не задевает — анимируется только смена адреса. Если браузер уже анимировал переход сам (свайп от края «назад» / «вперёд» в iPhone Safari), наша анимация для этого перехода не проигрывается — двойной анимации нет; следующий переход анимируется как обычно. Браузер, который об этом не сообщает, получает обычную анимацию «назад».

**Смена блюда в калькуляторе** — не смена экрана: шапка с полкой блюд остаётся на месте, не перерисовывается и не анимируется, меняется только отметка текущего чипа. Под полкой калькулятор нового блюда въезжает коротко (150 мс): из прозрачного и сдвинутого на 16 px. Сторона — по чипу на полке: чип правее текущего — новое содержимое въезжает справа, левее — слева (порядок полки, какой он был на момент тапа; пока полка открыта, он не меняется). Если блюдо открыто не чипом (меню блюд, «назад» / «вперёд» по истории) — как между экранами: вперёд справа, назад слева, при замене адреса — без анимации. Полка сама не прыгает: прокручивается, только если текущий чип не виден целиком (до края, за затемнение), и ровно настолько, чтобы его было видно, — плавно, при «уменьшить движение» и при открытии экрана — сразу. Ввод анимацию не запускает.

## 2. Основные потоки

### П0. Настроить один раз
1. Настройки → «Компании» → «+ Компания» → в поле «+ Имя» сразу фокус: «Ваня», Enter, «Ксюша», Enter → полоса долей, как в калькуляторе: тянем границу или «− Ваня +» до 54 : 46. Название можно не писать — будет «Ваня и Ксюша». Вторая: «С тёщей» — Ваня, Ксюша, Тёща, доли 37 : 32 : 31.
2. «⋯» → «Добавить блюдо» → форма «Добавить блюдо»: «Макароны 130» (переключатель вверху — «Простое»; добавили «Соль» с «не учитывать» — по-прежнему «Простое»; добавили «Фарш» — «Составное»; «Составное» можно выбрать и сразу — появится строка для второго продукта), тара → **«Создать»**. Пока не нажато «Создать», ничего не сохраняется; «Отмена» возвращает назад. Или 🔍 → «макар» → «Макароны · 250 г» из популярных в меню блюд — блюдо добавлено и открыто.

### П1. Сварить макароны (каждый день)
1. Открывает приложение — сразу калькулятор блюда, которым пользовались последним; другое — тап по чипу на полке или 🔍. «Сухой 130 г» (как в прошлый раз), «Ваня и Ксюша» с прошлыми долями.
2. Сегодня захотели побольше — тап по «Сухой» — 130 выделено, 1-5-0 заменяет его. Блюдо запоминает 150: в следующий раз будет 150.
3. Сварил, взвесил → тап «Готовый» (или «Далее» на клавиатуре) → 3-6-0 → «Готово», клавиатура закрывается. Сразу видит «Ваня 194 г», «Ксюша 166 г» (делится 70 : 60, сколько бы воды ни взяли макароны). Сохранять нечего: готовый вес тоже записан в блюдо с временем, и Ксюша на своём телефоне видит «Готовый 360 · 19:40» и свою порцию.
4. Приехала тёща → «Ваня и Ксюша ▾» → «С тёщей» → «Ваня 133 г», «Ксюша 114 г», «Тёща 114 г». Или в поле «+ Имя» внизу списка: «Тёща», Enter. Состав и доли запоминаются у этого блюда (у других блюд — свои), «Сохранить состав как компанию» в списке компаний превращает его в пресет. Новая компания прямо отсюда: в конце списка «Добавить компанию» → экран «Новая компания» (§3а) → «Добавить компанию» → снова калькулятор, компания выбрана.
5. Ване сегодня меньше → тап по его числу → 1-2-0 → Ване 120 г, Ксюше остальное по долям. Уходит из поля — его часть блюда запоминается как доля: в следующий раз сразу так.
6. ⧉ у своей строки → в буфере «Макароны (сырой вес) — 50 г».

### П2. Суп (составное)
1. «Составные» → «+ Составное блюдо» → «Суп», ингредиенты курица 600 … рис 80, вода 2000 «не учитывать» → «Создать».
2. Тап «Суп» на полке → продукты свёрнуты в «Сырой 1 080 г · не учит.: Вода 2 000 г» → вес после готовки 3160 → «k блюда = 1,03». Поправить сегодняшний вес продукта — «Продукты ⌄».
3. У каждого человека — готовый вес и состав в сыром виде («Курица 323 г · Картофель 215 г · Рис 43 г»). Своя порция — в граммах или процентах.

### П3. Остаток на завтра
Потянуть правый край полосы долей влево — «На завтра 20 %»: делящие получают меньше, под списком «В кастрюле останется — на завтра: 72 г» и сухой вес. Завтра — открыть блюдо, ввести этот сухой вес и новый готовый вес остатка. Отдельного перевзвешивания и этапов в приложении нет (этап 15).

### П3а. Составное на основе простого
1. «⋯» → «Изменить «Макароны»» → «Составное на основе» → редактор нового составного: первый ингредиент «Макароны 130 г», тара как у макарон; фокус на следующем ингредиенте.
2. Или в редакторе составного → «Из простого блюда» → «Макароны» → ингредиент добавляется в конец (пустая последняя строка заменяется).

### П3б. Meal prep на неделю (этап 16)
1. Сварил гречку на 6 дней (200 г сухой → 560 г готовой) → список «Кто ест» → «Доли». Вместо людей — «Порция 1» и «Порция 2» поровну, та же полоса долей во всю ширину, рядом с полем «Доли» — «− 2 +» → «+» четыре раза → «− 6 +», по 93 г и 33 г сухого.
2. В пятницу ужин плотнее: тап по числу «Порции 5» → 120 → она получает 120 г, остальные пять делят оставшиеся 440 г поровну по 88 г. ⧉ у порции — «Гречка (сырой вес) — 31 г».
3. Тап по «Сухой» — те же порции в граммах сухого; своя порция вводится в сухом виде. Ползунком можно сделать одну порцию больше другой, «Поровну» — снова равные.
4. В среду решил есть её 5 дней → «−» рядом с «Доли» → «− 5 +». Открывает макароны — тоже «Доли», порции у макарон свои. Вернуться к людям — выбрать компанию в том же списке: состав и доли блюда на месте.
5. Режим и порции остаются на этом телефоне: у Ксюши в той же группе калькулятор показывает её собственный выбор.

### П4. Новая тара прямо у плиты
Под плитками тап по таре → в конце списка «Добавить тару» → список закрывается, открывается экран «Новая тара» (§3а) с той же формой, что в настройках: «Название» → Enter → «Вес» → Enter (или «Добавить тару») → тара записана в библиотеку, выбрана и запомнена у блюда, над формой появился список «Добавлено». Форма снова пустая, фокус в «Название» — тут же можно добавить следующую (миску, сковороду). Выбранной остаётся первая добавленная — та, ради которой открыли экран; тап по другой строке в «Добавлено» выбирает её. «Готово» — снова калькулятор, выбранная тара в поле. «←» — тоже назад: что уже добавлено, остаётся; пока ничего не добавлено — назад без новой тары.

Если тару блюда потом удалили в настройках, блюдо открывается с «Без тары» (SPEC §8): список не бывает пустым.

### П5. Установить на iPhone (этап 11)
1. Safari → адрес приложения → «Поделиться» → «На экран „Домой“» → «Порции».
2. Иконка открывает приложение без строки Safari, сразу на последнем блюде. Без сети всё работает.
3. Данные из Safari сюда не переезжают: у приложения на экране «Домой» своё хранилище. Перенести — войти в аккаунт (П6) или «Копия данных»: «Скачать» в Safari, «Загрузить» в приложении.
4. После обновления на сервере при следующем открытии — тост «Есть новая версия · Обновить». Пока не нажато, работает старая версия.

### П6. Аккаунт и общий учёт с Ксюшей (этапы 12–14)
1. **Ваня:** Настройки → «Аккаунт» → «Войти» → «Создать аккаунт»: почта, пароль (iPhone предлагает сохранить его в Связке ключей) → его блюда теперь в группе «Личная». «Добавить вход по Face ID».
2. Настройки → «Группа» → «Пригласить» → код `K7MR-Q2XD` крупно и «Поделиться» → ссылка в Telegram Ксюше.
3. **Ксюша:** ссылка открывается в Safari → «Создать аккаунт» → «Вступить в группу „Личная“? Пригласил: vanya» → «Вступить» → «Открывать эту группу при запуске?» → «Да».
   Если приложение у неё уже на экране «Домой»: Safari показывает код, она открывает приложение → Настройки → «Группа» → «Вступить по коду».
4. Теперь у обоих одни блюда, тара и компании; готовый вес, который ввела Ксюша, через минуту (или при открытии приложения) виден у Вани в этом блюде: «Готовый 360 · 19:40».
5. Без сети всё работает; в «Аккаунте» — «Нет сети — изменения сохранены на устройстве». Сеть появилась — «Синхронизировано · 19:42».

## 3. Поведение элементов

- **Полка блюд** (шапка калькулятора): 🔍 — одна круглая кнопка в начале, вне прокрутки, с подсказкой при наведении «Найти блюдо ⌘K /»; открывает меню блюд. ⌘K / Ctrl+K и «/» (когда курсор не в поле) открывают его же. Дальше чипы (36 px на вид, 44 px для пальца) по последнему использованию; текущий обведён, тап по другому открывает его калькулятор. Пока полка открыта, порядок не меняется; новое блюдо встаёт в начало. «⋯» справа.
  - *Что поднимает блюдо в начало* (`updatedAt`, общий для группы): создание («Создать», «Составное на основе», популярное из поиска или «Популярных блюд»), «Сохранить» в редакторе и ввод в калькуляторе того, что блюдо запоминает, — сухой вес, тара, готовый вес; так же — на другом устройстве группы. *Не поднимают:* просто открыть блюдо (чип, меню блюд), скопировать ответ, «Кто ест» и доли — они хранятся отдельно от блюда (`lineups`), и их правка не перезаписывает блюдо, которое в это время меняют на другом устройстве.
  - *Когда полка пересортировывается:* когда открывается калькулятор (запуск, возврат из редактора, меню блюд, настроек) и когда возвращаешься в приложение из фона. Тап по чипам переключает блюда без пересортировки: чип не уезжает из-под пальца. Блюда, появившиеся при открытой полке (добавлено из меню блюд, пришло из группы), встают в начало; удалённые исчезают.
- **Меню блюд** (`#/dishes`, экран во весь экран §3а — на телефоне и на десктопе, палитры поверх нет): заголовок «Блюда», под ним поле поиска, фильтр по типу и сортировка; ниже список.
  - *Поле поиска сразу в фокусе и клавиатура открыта* (iPhone в Safari и установленной PWA, Android, десктоп): сразу печатаем. Поле 16 px, клавиша клавиатуры — «Перейти» (`enterKeyHint="go"`), ✕ в поле очищает его и оставляет фокус. На iPhone клавиатура открывается, только если поле получило фокус прямо в обработчике тапа, поэтому тап по 🔍 сначала фокусирует невидимое поле, которое всегда есть на странице, и уже потом открывает экран — фокус переходит в настоящее поле, клавиатура остаётся.
  - *Фильтр по типу* — «Все · Простые · Составные» (`ToggleGroup`), по умолчанию «Все»; действует и на свои блюда, и на популярные.
  - *Сортировка* — `Select`: «Частые» (по умолчанию) и «По названию» (SPEC §3б, «Меню блюд»). Пока в поле есть текст, сначала лучшие совпадения, выбранная сортировка — среди равных.
  - *Список:* «Ваши блюда» — строка 44 px и выше, слева название, справа вес или состав; тап открывает калькулятор. Ниже «Популярные — добавить» (каталог «Популярных блюд», которых ещё нет, с весом): тап — блюдо создано и открыто, тост «Блюдо добавлено · Булгур · 150 г · Отменить». Ничего не подошло — «Ничего не нашлось».
  - *С клавиатуры:* Enter («Перейти» на телефоне) открывает выделенное блюдо — сначала это первое в списке; на десктопе ↑ / ↓ двигают выделение; Esc сначала очищает поле, потом закрывает экран (как «←»).
  - *Адрес* хранит всё, что на экране: `#/dishes?q=гре&kind=composite&sort=name` (по умолчанию параметров нет; при наборе и переключении адрес заменяется, новых записей в истории нет). «Назад» из калькулятора возвращает в то же меню с тем же текстом, фильтром и сортировкой.
  - *Без блюд* это первый экран (`#/`): «Пока нет блюд», «Блюдо», «Популярные блюда» — как раньше, без поиска.
- **«⋯»** (`DropdownMenu`, пункты 44 px) — во всех шапках: действия экрана, разделитель, «Настройки». Калькулятор: «Изменить «Гречка»», «Добавить блюдо». Меню блюд: «Добавить блюдо».
- **Редактор блюда:** черновик живёт в форме, сохраняется только кнопкой «Создать» / «Сохранить» (неактивна, пока не хватает данных; под ней текст, чего не хватает). Заголовок — «Добавить блюдо» / «Изменить блюдо». Вверху переключатель «Простое | Составное» (`ToggleGroup`, SPEC §3). Строки ингредиентов (название · сырой вес · ×, «не учитывать»), «+ Ингредиент», «Из простого блюда», «Название», «В чём взвешиваете» (по умолчанию «Без тары»). У существующего блюда внизу — «Составное на основе» (у простого) и «Удалить блюдо» (`AlertDialog`).
- **Плитки калькулятора:** «Сухой» (у составного свёрнутого — «Сырой ⌄» с суммой и пометкой «не учит.: …») и «Готовый» в ряд; подпись «Готовый · 19:40», если подставлен сегодняшний расчёт. Под плитками — тара, «без тары · k», у составного — «Продукты ⌄» / «Свернуть ⌃». Плитка в фокусе задаёт вид порций (SPEC §3б): «Готовый» — граммы людей и полосы готовые, под именем «38 г сухого»; «Сухой» — граммы сухого, под именем «100 г готового», своя порция вводится в сухом виде.
- **Компания в калькуляторе** (`Select` над полосой долей): выбор подставляет людей и доли компании в состав блюда; выбранная компания так и остаётся в поле, когда двигают ползунок или добавляют людей — компания и её название от этого не меняются. Состав и доли запоминаются у каждого блюда отдельно. Последний пункт — «Добавить компанию»: экран «Новая компания» (§3а) открывается, когда список закрылся, фокус в «+ Имя»; форма та же, что в настройках (`CompanyForm`). После «Добавить компанию» — снова калькулятор, новая компания выбрана в поле.
- **«Доли» в списке «Кто ест»** (этап 16, SPEC §3б): пункт после компаний (иконка — круговая диаграмма), до разделителя и действий. Выбран — в поле «Доли», вместо людей безымянные «Порция 1 … Порция 6» с той же полосой и своей порцией (граммы, проценты, «Сухой» / «Готовый»). Вместо строк — **ответ одной строкой и сетка контейнеров** (этап 17): сверху «по 80 г × 7 · 29 г сухого» и ⧉ («Скопировать для трекера: одна порция» — у равных порций текст для трекера один), под ним, если есть свои, — «своя: 5 — 120 г»; порции разные (после ползунка) — «73–79 г · 7 порций по долям». Ниже — контейнеры по три в ряд (по два уже 360 px, по четыре с `lg`): номер в метке-крышке, число крупно (тап — своя порция, как у человека), под ним сухой вес (в «Сухом» — готовый). ⧉ у контейнера — когда порции разные и у своей; у равных копирует строка ответа. Своя порция — пунктирная рамка, как её сегмент на полосе; «своя ×» в контейнере нет (на троих в ряд места хватает одной кнопке): стёртое число возвращает порцию к доле, «Сбросить свои» — все сразу. Свайпов в сетке нет: порции нумеруются по месту, поэтому «−» рядом с «Доли» и есть «убрать порцию». Имя у порции не правится. На сегментах полосы — номер порции («3» над граммами) вместо «Порция 3»: он помещается и в узкий сегмент, где имя уже пропало бы, и различает порции, когда их больше, чем крышек. «На завтра» нет. Число порций — в той же строке, справа от поля «Доли»: «− 6 +» (`ButtonGroup`, 44 px; «−» неактивна на 1, «+» — на 100), полоса под ними — во всю ширину. Под полосой — «− Порция 1 +» для выбранной порции, как у людей: сначала первой (обведена, ручки по её краям — поэтому ручки есть всегда), тап по сегменту выбирает другую. Строки «+ Имя» внизу списка нет, список кончается последней порцией. «Сохранить состав как компанию» в режиме долей не показывается. Чтобы вернуться к людям — выбрать компанию; если у блюда был свой состав без компании, в режиме долей в списке есть пункт «Свой состав · 4» — он возвращает этот состав. Режим и порции — на этом устройстве для всех блюд.
- **Новая тара** — одна форма везде (настройки, экран «Новая тара» из калькулятора), крупная: «Название» и «Вес» друг под другом, поля высотой 56 px с текстом 18 px, вес — только числом в поле (ползунка нет); кнопка «Добавить тару» обычного размера (44 px) справа под полями — на экране «Новая тара» она не больше главной кнопки «Готово» внизу; неактивна, пока нет названия и веса больше 0. Enter в «Название» переводит в «Вес», Enter в «Весе» добавляет тару. **Несколько тар за раз:** после добавления форма очищается, фокус снова в «Название» (клавиатура телефона не прячется) — сразу вводится следующая. В настройках новая тара сразу видна строкой в списке над формой; на экране «Новая тара» — в списке «Добавлено» над формой («Миска · 320 г», у выбранной — галочка), экран открыт, пока не нажали «Готово» или «←».
- **Компании в настройках:** правятся на месте тем же интерфейсом, что «Кто ест» в калькуляторе (SPEC §3б): название, полоса долей (тянуть границы, «− Ваня 54 % +», «Поровну»; без «На завтра» и без «г | %» — блюда здесь нет, только проценты), под ней люди (имя · % с одним знаком, «33,3 %» · × удержанием, как в калькуляторе), внизу поле «+ Имя» (Enter — человек добавлен с долей, средней по остальным, поле готово для следующего). Новая компания открывается пустой, с фокусом в «+ Имя». Удаление компании — с тостом «Отменить».
- **Копирование:** тост «Скопировано» с первой строкой текста; без доступа к буферу — экран с выделенным текстом (§3а).
- **Свайпы строк (телефон и iPad):** устройство определяем по вводу (`pointer: coarse`), а не по ширине — iPad тоже получает свайпы. Строка едет за пальцем, под ней проступает действие: свайп влево — красное «Убрать», свайп вправо — «Копировать». Отпустил после короткого свайпа (от 48 px) или быстрого взмаха — строка доезжает и остаётся открытой на действии (тап по нему — сделать, тап по строке — закрыть; взмах обратно — закрыть); свайп на полстроки и дальше — действие сразу. Взмах сам по себе действие не делает — только расстояние. Открыта только одна строка: начал свайп или тапнул по другой — открытая закрывается. Вертикальная прокрутка свайп не запускает. Удаление свайпом — с тостом «Убрано: Ваня · Отменить» (у ингредиента — «Удалено: Курица · Отменить»). Иконки ⧉ и × на сенсорном экране скрыты, но остаются для клавиатуры и экранного диктора. С мышью и трекпадом (десктоп) — иконки, как раньше, свайпов нет.
  - **Анимации.** Под пальцем строка едет 1:1, без задержки; за краем (вправо у строки без «Копировать», дальше ширины строки) — тянется с сопротивлением. Отпустил — строка доезжает за 150–250 мс с замедлением в конце, тем быстрее, чем быстрее был взмах. Действие под строкой проявляется и подрастает по мере свайпа, а когда отпускание уже сделает действие — чуть увеличивается. Удаление (полный свайп, тап по «Убрать», × на десктопе): строка уезжает влево, потом её высота плавно схлопывается и строки ниже поднимаются, без скачка; «Отменить» — строка возвращается на место, раскрываясь по высоте с проявлением (≈200 мс).
  - **Меньше движения** (`prefers-reduced-motion: reduce`): строка под пальцем по-прежнему едет, но все переходы мгновенные — без доезда, уезжания, схлопывания и раскрытия.
  - Человек в калькуляторе: влево — убрать из сегодняшнего состава, вправо — скопировать для трекера. На десктопе × по-прежнему удержанием; удержал — строка уезжает и схлопывается так же, как после свайпа.
  - Порции в «Доли» — сетка без свайпов (§3, этап 17): «−» рядом с «Доли» убирает последнюю, ⧉ в контейнере или в строке ответа копирует.
  - Ингредиент в редакторе блюда и тара в настройках: только влево — удалить.
  - Участники группы: × удержанием и на телефоне — удаление идёт на сервер, вернуть тостом нельзя.
- **Удаление** блюда — через `AlertDialog` в редакторе; вместе с ним уходит его состав «Кто ест».
- **Ошибки ввода** — под полем, красным, текстом.

- **Компоновка (после /impeccable adapt distill):** без карточек — секции с заголовками и отступами; главная кнопка экрана («Создать / Сохранить») на телефоне прилипает к низу под большой палец, на десктопе стоит сразу после основного содержимого. На телефоне «назад» в шапке — только стрелка. В калькуляторе «Сухой» и «Готовый» в одном ряду, под ними одна тихая строка «Без тары · k = 2,4»; у человека имя и сухой вес слева, готовый вес крупно справа.

- **Цвета едоков:** у каждого человека из сегодняшнего состава свой цвет крышки (небо, подсолнух, мята, сирень, абрикос, бирюза, роза, фисташка, лаванда, пион — десять, чтобы хватило на meal prep на 10 дней; с одиннадцатого — по кругу). Им окрашены его сегмент в полосе долей (48 px, имя и под ним граммы; между полосой и «− Ваня +» 12 px) и метка у имени. Своя порция в граммах — та же крышка бледнее, с пунктирной рамкой; в тёмной теме — крышка контуром: фон почти ночной, число и пунктир цвета крышки (бледная крышка на ночном фоне выходила грязно-коричневой). Выбранный для «±1 %» — обведён, цвет сохраняется. Ручки на границах — там, где соседям хватает места (сегменты от 4 rem); у краёв выбранного — всегда, поэтому при 6–7 порциях на телефоне полоса показывает граммы, а ручки появляются у сегмента, по которому тапнули. Различие дублируется именем, не только цветом.
- **Курсор калькулятора** — системный курсор поля; его цвет примерно с каждым миганием переходит на крышку следующего едока. Без людей и при «уменьшить движение» — основной цвет.
- **Поля калькулятора** не похожи на поля ввода: число без рамки, шириной по себе, «г» сразу за ним. Поле в фокусе — белая «коробка» с рамкой на матовом фоне.

## 3а. Экраны и окна поверх

Правило для всех экранов, новых и существующих (2026-10-06).

**Где много контента — отдельный экран во весь экран.** Много — это поле ввода, поиск, список с прокруткой или больше пары строк текста. Сюда относятся создание и правка (блюдо, тара, компания), вход, «Вступить по коду», поиск (меню блюд), выбор из списка с поиском («Из простого блюда»), показ текста для копирования. Для них не используем `Dialog`, `Sheet`, `Drawer` или `Popover`.

Такой экран:
- **во весь экран телефона:** шапка с «←» (на телефоне только стрелка) и заголовком — что делаем («Новая тара», «Вступить по коду»), главная кнопка внизу (`BottomBar`), с учётом выреза и полоски «Домой»;
- **со своим адресом** `#/…`: системный «назад» (свайп от края на iPhone, кнопка «назад» на Android и в браузере) работает так же, как «←», после перезагрузки открывается тот же экран. Поиску и выбору из списка адрес не обязателен, но системный «назад» должен их закрывать;
- **возвращает в то же состояние.** «←» и системный «назад» ведут ровно туда, откуда экран открыли: тот же экран, то же блюдо, тот же подраздел, та же прокрутка, те же раскрытые блоки. Черновик не сохраняется, как в редакторе блюда;
- **после главной кнопки** («Готово» на экране «Новая тара», «Добавить компанию») — тоже назад, и результат уже на месте: тара выбрана у блюда, компания — в поле компании, фокус на поле, из которого открывали. Заполненная форма уходит из истории: системный «назад» на неё не возвращает. Исключение — «Создать» в редакторе блюда: открывается калькулятор нового блюда. На экране «Новая тара» «Добавить тару» с экрана не уводит — можно добавить несколько подряд (§3), назад ведёт «Готово»;
- **фокус** — в первом поле;
- **переход анимируется:** вглубь и назад — в разные стороны; при «уменьшить движение» — без анимации (§1 «Переходы между экранами»).

**Открытие из списка или меню.** Пункт, который открывает экран («Добавить тару», «Добавить компанию»), — последний в списке, после разделителя, с «+»: он выглядит как действие, а не как значение. По тапу сначала закрывается список (`Select`, `DropdownMenu`, `Popover`), значение поля не меняется, потом открывается экран. При возврате фокус — на поле, из которого открывали.

**Поверх экрана — только короткое:**
- подтверждение — `AlertDialog`: вопрос, одна-две строки пояснения, две кнопки («Удалить блюдо?», «Перенести данные этого устройства?»). Так же устроены подтверждения в iOS и Android;
- меню «⋯» (`DropdownMenu`) и выбор из списка без поиска и без полей (`Select`);
- подсказки (`Tooltip`) и тосты (`Sonner`).

Если в окне понадобилось поле ввода, поиск или прокрутка — это уже экран.

**Планшет и десктоп (с `md`).** Формы — те же экраны по тем же адресам, одна колонка ≤ 720 px по центру, как редактор блюда. Меню блюд — тоже экран и на десктопе (⌘K открывает его, палитры поверх нет).

Экран поверх другого — его дочерний адрес (`#/d/<id>/tare/new`): экран под ним остаётся открытым, только спрятан, поэтому «назад» возвращает его как было — те же введённые числа, свои порции, черновик. Переход тот же, что между экранами (§1 «Переходы между экранами»): экран поверх въезжает справа, при «назад» экран под ним — слева. «Из простого блюда» — экран на всех ширинах.

### Настройки
Разбиты на подразделы, у каждого свой адрес `#/settings/<подраздел>` (назад/вперёд и перезагрузка возвращают туда же):

| Подраздел | Адрес | Что внутри | Подпись в меню |
|---|---|---|---|
| «Тара» | `tares` | справочник тары | «Вес пустой посуды» |
| «Компании» | `companies` | компании; под ними «Убрать человека» (сколько держать ×: Сразу / 1 с / 1,5 с / 2 с) — тоже про людей | «Кто ест вместе» |
| «Популярные блюда» | `presets` | кнопка «Добавить популярные блюда»: около 30 простых и 20 составных рецептов с обычным весом, без тары; добавляются к своим блюдам в конец списка, блюда с таким же названием пропускаются; если в приложении уже есть блюда — сначала подтверждение; после добавления тост с «Отменить»; когда добавлять нечего, кнопка неактивна с подписью «Все популярные блюда уже добавлены» | «Готовые рецепты для начала» |
| «Копия данных» | `data` | «Скачать» / «Загрузить» JSON-файл; загрузка — после подтверждения, с «Отменить». Вошли — подтверждение говорит, что данные группы заменятся у всех её участников. | «Оформление» | `appearance` | «Тема»: Как в системе / Светлая / Тёмная (по умолчанию — как в системе). Выбор запоминается в этом браузере и не попадает в копию данных | «Светлая или тёмная тема» |

| «Группа» (этап 14, только после входа) | `group` | Выбор группы (если их несколько; чужая — «Личная · vanya») и ★ «Открывается при запуске» / «Открывать при запуске»; название (правит владелец, на месте); участники (× удержанием — убрать, только владелец); «Пригласить»; «Вступить по коду»; «Выйти из группы» (только в чужой группе) | Название открытой группы |

**Телефон (< 768 px):** `#/settings` — список подразделов (иконка, название, подпись, «›»). Тап открывает подраздел отдельным экраном: в шапке «←» обратно к списку (или туда, откуда открыли подраздел, например «Популярные блюда» из пустого списка блюд) и название подраздела; «←» в списке — туда, откуда пришли в «Настройки». Нижнее меню остаётся на всех экранах настроек, «Настройки» в нём активны.

**Планшет и десктоп (≥ 768 px, `md`):** слева меню подразделов, справа выбранный подраздел, «←» в шапке — туда, откуда пришли в «Настройки». Из открытого подраздела переключение в меню заменяет адрес, а не добавляет запись в историю. На `#/settings` справа открыт первый подраздел («Аккаунт», с этапа 12; до него — «Тара») и он же подсвечен в меню.

Внутри подразделов — списки-строки: сводка читается, тап по строке раскрывает правку на месте (открыта одна строка списка). Новая компания сразу открыта.

### Вход (`#/account`, этап 12)
```
│ ←  Аккаунт                          │
│ [ Войти | Создать аккаунт ]         │
│ Почта   [ vanya@example.com       ] │
│ Пароль  [ ••••••••                ] │
│ [            Войти              ]   │
│ [  ◉ Войти с Face ID            ]   │
│ Забыли пароль?                      │
```
- Поля: `autocomplete="email"`, `"current-password"` / `"new-password"` — iPhone предлагает и сохраняет пароль. В поле почты iPhone сам предлагает Face ID, если он уже добавлен.
- Без сети: после нажатия «Войти» — «Нет сети — войти можно, когда она появится».
- «Забыли пароль?» (пока нет писем): нужна почта в поле; под полями — «Ссылку для нового пароля пришлёт владелец приложения — напишите ему». По ссылке — экран «Новый пароль» (`#/account/reset`) → «Сохранить пароль» → тост «Пароль изменён — войдите с ним».
- Ошибки — под полем пароля, свои, по-русски (подсказки браузера выключены): «Пароль — не короче 8 символов», «Неверная почта или пароль», «Такая почта уже зарегистрирована», «Нет сети — войти можно, когда она появится», «Face ID не сработал — войдите паролем».
- После входа — в Настройки → «Аккаунт». Данные, которые были на устройстве без аккаунта, переезжают в группу «Личная»: молча, если в ней пусто; иначе `AlertDialog` «Перенести данные этого устройства?» → «Перенести» / «Не переносить». Копия данных устройства в любом случае остаётся в браузере.

### Аккаунт и группа (Настройки, этапы 12–14)
```
Аккаунт                               Группа
│ vanya@example.com                │  │ [ Личная ★              ⌄ ]   │
│ ✓ Синхронизировано · 19:42       │  │ Название [ Личная         ]   │
│ ◉ Face ID добавлен               │  │ Участники                     │
│ [ Выйти ]                        │  │ vanya · владелец              │
                                      │ ksusha                     ×  │
                                      │ [ + Пригласить ]              │
                                      │ Вступить по коду              │
                                      │ Выйти из группы               │
```
- «Вступить по коду» открывает экран с полем кода (§3а), «Дальше» — экран «Вступить в группу».
- «Пригласить» раскрывает на месте: код крупно (`K7MR-Q2XD`, моноширинные цифры), ссылка, «Копировать» и «Поделиться», «Действует до 13 окт.», у владельца — «Отозвать».
- Звёздочка у группы по умолчанию; у другой группы в списке — «Открывать при запуске».
- Переключение группы открывает список блюд этой группы.
- Статус синхронизации — одной строкой под почтой. Если нужно действие («Войдите снова…» — с кнопкой «Войти снова», «Обновите приложение…», «Нет доступа к группе»), на пункте «Настройки» в нижнем меню — точка цвета `--warning`. «Нет сети…» — обычный режим, без точки.
- «Выйти» из аккаунта: если не всё отправлено — «Не все изменения отправлены. Выйти всё равно?».

## 5. Десктоп (≥ 1024 px, `lg`)

Калькулятор — одна колонка ≤ 28rem по центру; курсор сразу в первом пустом поле, Enter или ↓ — следующее поле, ⌘K и «/» — меню блюд. Меню блюд и редактор — одна колонка шириной ≤ 720 px по центру; настройки — меню подразделов слева и выбранный подраздел справа (уже с `md`, см. «Настройки» выше).
