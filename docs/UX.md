# UX: экраны и потоки (MVP)

Статус: черновик на ревью · 2026-10-01. Термины — в [SPEC.md §2](SPEC.md#2-глоссарий).

## 1. Карта экранов

Два режима: **калькулятор** (каждый день: открыл — блюдо уже выбрано или в один тап на полке, ввёл готовый вес — видишь, сколько класть каждому) и **настройка** (блюдо, компании, тара — редко, с явным «Создать» / «Сохранить»). Калькулятор устроен как конвертер величин (SPEC §3б). С этапа 15 нет нижнего меню, готовок и истории.

```
┌──────────────────────────────────────┐  «⋯» → Изменить «Гречка» → Редактор #/d/<id>/edit
│ 🔍 (Гречка) Макароны Рис …         ⋯ │  «⋯» → Добавить блюдо     → Редактор #/d/new
├──────────────────────────────────────┤  «⋯» → Настройки          → #/settings
│ Калькулятор #/d/<id>  (главный, #/ → │  🔍, ⌘K, «/» → Меню блюд #/dishes: поиск, разделы «Часто
│ последнее блюдо)                     │       готовишь» и «Остальные», популярные; «+» в шапке — Добавить блюдо
│ Сухой 70 г | Готовый 186 г           │
│ Кто ест · полоса долей · люди        │  Без блюд #/ — то же меню: «Добавить блюдо», популярные
│ (клавиатура — системная, по тапу)    │  Аккаунт #/account · ссылка-приглашение → Вступить #/join/<код>
└──────────────────────────────────────┘
```

**Первый запуск** (этап 18): на устройстве нет блюд и приветствие не пройдено — `#/` открывает приветственный экран `#/welcome` (§3в): о приложении и об аккаунте. При первом открытии калькулятора — тур по нему (§3б).

Экраны поверх другого (§3а) — его адрес плюс шаг: «›» в углу плитки «Сырой» (составное блюдо) → «Ингредиенты» `#/d/<id>/ingredients`; тара ▾ «Добавить тару» → «Новая тара» `#/d/<id>/tare/new`; «Кто ест ▾» «Добавить компанию» → «Новая компания» `#/d/<id>/company/new`; «Из блюда» в редакторе → «Из блюда» `…/edit/from-dish` (у нового блюда `#/d/new/from-dish`); «+» у тары в редакторе → «Новая тара» `…/edit/tare/new` (у нового блюда `#/d/new/tare/new`); копирование без доступа к буферу → «Скопируй вручную» `…/copy` (калькулятор, Настройки → «Группа»); Настройки → «Группа» → «Вступить по коду» → `#/join`; Настройки → «Группа» → группа → её экран `#/settings/group/<id>`; Настройки → «Аккаунт» → фото → «Фото» `#/settings/account/photo`.

**Шапки.** На калькуляторе — полка блюд (🔍 «Найти блюдо» в начале вне прокрутки, чипы по последнему использованию, «⋯» справа). На остальных экранах — «← назад», заголовок и «⋯» с действиями экрана и «Настройками» (везде одно меню). Точка «нужно внимание» (синхронизация) — на «⋯» и на пункте «Настройки».

**«Назад».** «←» в шапке и «Отмена» возвращают на экран, с которого открыли этот, с теми же параметрами (то же блюдо, тот же подраздел настроек, прокрутка): это шаг назад по истории, ровно как системный «назад» (кнопка браузера, свайп от края на iPhone), и новых записей в истории он не добавляет. Примеры: калькулятор «Гречки» → «⋯» → «Добавить блюдо» → «←» — снова калькулятор «Гречки»; «Изменить блюдо» → «Сделать составным» → «←» — форма простого блюда → «←» — калькулятор; «Настройки», открытые с любого экрана, — назад на него; «Аккаунт» — туда, откуда открыли («Настройки», строка синхронизации, «Вступить в группу»). Подпись у «←» (с `sm`, на телефоне только стрелка) — «Назад». Если предыдущего экрана в приложении нет (открыли по прямой ссылке), «←» ведёт на запасной экран, заменяя текущий в истории, и подписан его названием:

| Экран | Запасной «назад» |
|---|---|
| Меню блюд, «Настройки», «Вступить в группу» | калькулятор (`#/`) |
| «Ингредиенты», «Новая тара», «Новая компания» | калькулятор этого блюда («Новая тара» из редактора — форма блюда) |
| «Из блюда» | форма блюда |
| «Скопируй вручную» | экран, с которого копировали |
| Экран группы | Настройки → «Группа» |
| «Фото» | Настройки → «Аккаунт» |
| «Вступить по коду» | «Настройки» → «Группа» |
| подраздел настроек (телефон) | список «Настроек» |
| «Добавить блюдо» | меню блюд |
| «Изменить блюдо» | калькулятор этого блюда |
| «Аккаунт» | «Настройки» → «Аккаунт» |
| «Новый пароль» | «Аккаунт» |

После «Создать» / «Сохранить» форма заменяется калькулятором блюда, после удаления блюда — калькулятором (`#/`): «назад» на форму не возвращает.

**Переходы между экранами.** Новый экран въезжает коротко (200 мс): из прозрачного и сдвинутого на 24 px. Вглубь (калькулятор → форма, «Настройки» → подраздел, калькулятор → меню блюд (🔍, ⌘K, «/») → блюдо) — справа налево; назад («←», «Отмена», системный «назад» в браузере и на Android, свайп от края на iPhone; «вперёд» в браузере выглядит так же) — слева направо. Уходящий экран не анимируется, шапка едет вместе с экраном. Без анимации: при открытии и перезагрузке страницы, при замене адреса (после «Создать» / «Сохранить» / удаления, запасной «назад» без предыдущего экрана) и при «уменьшить движение». «Настройки» со всеми подразделами — один экран (как калькулятор со всеми блюдами): переход между экранами играется только при входе в них и выходе. На телефоне список → подраздел и обратно анимируется внутри экрана так же, как между экранами (вглубь справа, назад слева); с `md` переключение подраздела в меню анимирует только содержимое справа (150 мс, из прозрачного и сдвинутого на 8 px: подраздел ниже по меню — снизу, выше — сверху), меню и шапка стоят на месте. Во время перехода нет горизонтальной прокрутки; ввод он не задевает — анимируется только смена адреса. Если браузер уже анимировал переход сам (свайп от края «назад» / «вперёд» в iPhone Safari), наша анимация для этого перехода не проигрывается — двойной анимации нет; следующий переход анимируется как обычно. Браузер, который об этом не сообщает, получает обычную анимацию «назад».

**Смена блюда в калькуляторе** — не смена экрана: шапка с полкой блюд остаётся на месте, не перерисовывается и не анимируется, меняется только отметка текущего чипа. Под полкой калькулятор нового блюда въезжает коротко (150 мс): из прозрачного и сдвинутого на 16 px. Сторона — по чипу на полке: чип правее текущего — новое содержимое въезжает справа, левее — слева (порядок полки, какой он был на момент тапа; пока полка открыта, он не меняется). Если блюдо открыто не чипом (меню блюд, «назад» / «вперёд» по истории) — как между экранами: вперёд справа, назад слева, при замене адреса — без анимации. Полка сама не прыгает: прокручивается, только если текущий чип не виден целиком (до края, за затемнение), и ровно настолько, чтобы его было видно, — плавно, при «уменьшить движение» и при открытии экрана — сразу. Ввод анимацию не запускает.

## 2. Основные потоки

### П0. Настроить один раз
1. Настройки → «Компании» → «+ Компания» → в поле «+ Имя» сразу фокус: «Ваня», Enter, «Ксюша», Enter → полоса долей, как в калькуляторе: тянем границу или «− Ваня +» до 54 : 46. Название можно не писать — будет «Ваня и Ксюша». Вторая: «С тёщей» — Ваня, Ксюша, Тёща, доли 37 : 32 : 31.
2. «⋯» → «Добавить блюдо» → форма «Добавить блюдо»: в поле «Что в блюде» — «макароны 130» (или микрофон: «макароны сто тридцать грамм»), под полем разбор «Макароны 130 г» и итог «Простое · сухой 130 г»; дописали «, соль 5» — соль сама «не в счёт», блюдо по-прежнему простое; дописали «, фарш 300» — «Составное · сырой 430 г». Тара — чип «Кастрюля 850 г» → **«Создать»**. Пока не нажато «Создать», ничего не сохраняется; «←» возвращает назад. Или 🔍 → «макар» → «Макароны · 250 г» из популярных в меню блюд — блюдо добавлено и открыто.

### П1. Сварить макароны (каждый день)
1. Открывает приложение — сразу калькулятор блюда, открытого последним на этом устройстве (после перезапуска или сбоя — с тем, что было введено сегодня: «Готовый», свои порции, «На завтра»); другое — тап по чипу на полке или 🔍. «Сухой 130 г» (как в прошлый раз), «Ваня и Ксюша» с прошлыми долями.
2. Сегодня захотели побольше — тап по «Сухой» — 130 выделено, 1-5-0 заменяет его. Блюдо запоминает 150: в следующий раз будет 150.
3. Сварил, взвесил → тап «Готовый» (или «Далее» на клавиатуре) → 3-6-0 → «Готово», клавиатура закрывается. Сразу видит «Ваня 194 г», «Ксюша 166 г» (делится 70 : 60, сколько бы воды ни взяли макароны). Сохранять нечего: готовый вес тоже записан в блюдо с временем, и Ксюша на своём телефоне видит «Готовый 360 · 19:40» и свою порцию.
4. Приехала тёща → «Ваня и Ксюша ▾» → «С тёщей» → «Ваня 133 г», «Ксюша 114 г», «Тёща 114 г». Или в поле «+ Имя» внизу списка: «Тёща», Enter. Состав и доли запоминаются у этого блюда (у других блюд — свои), «Сохранить состав как компанию» в списке компаний превращает его в пресет. Новая компания прямо отсюда: в конце списка «Добавить компанию» → экран «Новая компания» (§3а) → «Добавить компанию» → снова калькулятор, компания выбрана.
5. Ване сегодня меньше → тап по его числу → 1-2-0 → Ване 120 г, Ксюше остальное по долям. Уходит из поля — его часть блюда запоминается как доля: в следующий раз сразу так.
6. ⧉ у своей строки → в буфере «Макароны (сырой вес) — 50 г».

### П2. Суп (составное)
1. «⋯» → «Добавить блюдо» → «Суп», в поле «курица 600, картофель 400, морковь 160, лук 120, рис 80, вода 2 л, соль» (вода и соль сами «не в счёт», у воды пометка «из 2 л: считаем 1 мл ≈ 1 г») → «Создать».
2. Тап «Суп» на полке → рядом «Сырой 1 080 г · 5 ингредиентов, не в счёт: Вода, Соль» и «Готовый» → вес после готовки 3160 → «k блюда = 1,03». Поправить сегодняшний вес ингредиента — «›» в углу «Сырой» открывает экран «Ингредиенты»; «←» возвращает в калькулятор в сыром виде. Состав порции по ингредиентам — переключатель «Состав» в строке «Кто ест»: включён — рецепт виден под каждым человеком; запоминается на устройстве.
3. У каждого человека — готовый вес и состав в сыром виде («Курица 323 г · Картофель 215 г · Рис 43 г»). Своя порция — в граммах.

### П3. Остаток на завтра
Потянуть правый край полосы долей влево — «На завтра 632 г»: делящие получают меньше, под списком «В кастрюле останется — на завтра: 72 г» и сухой вес. Завтра — открыть блюдо, ввести этот сухой вес и новый готовый вес остатка. Отдельного перевзвешивания и этапов в приложении нет (этап 15).

### П3а. Сделать составным простого
1. «⋯» → «Изменить «Макароны»» → «⋯» → «Сделать составным» → редактор нового составного: в поле «Макароны 130, », курсор в конце; тара как у макарон.
2. Или в редакторе → «Из блюда» → «Макароны» → «Макароны 130» дописывается в конец фразы.

### П3в. Надиктовать у плиты (этап 19)
1. «Добавить блюдо» → микрофон в углу поля «Что в блюде» → «Слушаю…» → «курица шестьсот грамм картошка четыреста» → задумался → «вода два литра соль по вкусу» → тап по «стоп». Паузы запись не прерывают.
2. В поле дописалось «Курица 600, картошка 400, вода 2 л, соль по вкусу», под полем «Услышано: «курица шестьсот…»». Тоста нет. В разборе у воды «≈ 2 000 г» и пометка «из 2 л: считаем 1 мл ≈ 1 г». Сказанное между делом («я вот что-то говорю…») в ингредиенты не попадает — под «Услышано» строка «Пропущено: «я вот что-то говорю…»».
3. Или диктовкой с клавиатуры телефона: текст пришёл как есть, при выходе из поля он приводится к той же фразе — тост «Приведено к виду «ингредиент вес» · Отменить».

### П3б. Meal prep на неделю (этап 16)
1. Сварил гречку на 6 дней (200 г сухой → 560 г готовой) → список «Кто ест» → «Доли». Вместо людей — «Порция 1» и «Порция 2» поровну, та же полоса долей во всю ширину, рядом с полем «Доли» — «− 2 +» → «+» четыре раза → «− 6 +», по 93 г и 33 г сухого.
2. В пятницу ужин плотнее: тап по числу «Порции 5» → 120 → она получает 120 г, остальные пять делят оставшиеся 440 г поровну по 88 г. ⧉ у порции — «Гречка (сырой вес) — 31 г».
3. Тап по «Сухой» — те же порции в граммах сухого; своя порция вводится в сухом виде. Ползунком можно сделать одну порцию больше другой, «Поровну» — снова равные.
4. В среду решил есть её 5 дней → «−» рядом с «Доли» → «− 5 +». Открывает макароны — тоже «Доли», порции у макарон свои. Вернуться к людям — выбрать компанию в том же списке: состав и доли блюда на месте.
5. Режим и порции остаются на этом телефоне: у Ксюши в той же группе калькулятор показывает её собственный выбор.

### П4. Новая тара прямо у плиты
Под плитками тап по таре → в конце списка «Добавить тару» → список закрывается, открывается экран «Новая тара» (§3а) с той же формой, что в настройках: «Название» → Enter → «Вес» → Enter (или «Добавить тару») → тара записана в библиотеку, выбрана и запомнена у блюда, над формой появился список «Добавлено». Форма снова пустая, фокус в «Название» — тут же можно добавить следующую (миску, сковороду). Выбранной остаётся первая добавленная — та, ради которой открыли экран; тап по другой строке в «Добавлено» выбирает её. «Готово» — снова калькулятор, выбранная тара в поле. «←» — тоже назад: что уже добавлено, остаётся; пока ничего не добавлено — назад без новой тары.

Если тару блюда потом удалили в настройках, блюдо открывается с «Без тары» (SPEC §8): список не бывает пустым.

### П5. Установить на iPhone (этап 11)
1. Safari → адрес приложения → «Поделиться» → «На экран „Домой“» → «Порции».
2. Иконка открывает приложение без строки Safari, сразу на последнем блюде. Без сети всё работает.
3. Данные из Safari сюда не переезжают: у приложения на экране «Домой» своё хранилище. Перенести — войти в аккаунт (П6) или «Копия данных»: «Скачать» в Safari, «Загрузить» в приложении.
4. После обновления на сервере при следующем открытии — тост «Есть новая версия · Обновить». Пока не нажато, работает старая версия.

### П6. Аккаунт и общий учёт с Ксюшей (этапы 12–14)
1. **Ваня:** Настройки → «Аккаунт» → «Войти» → «Создать аккаунт»: почта, пароль (iPhone предлагает сохранить его в Связке ключей) → его блюда теперь в его группе (пока «Только ты»). «Добавить passkey» (Face ID на iPhone); на ноутбуке — ещё один passkey в Chrome.
2. Настройки → «Группа» → «Пригласить» → код `K7MR-Q2XD` крупно и «Поделиться» → ссылка в Telegram Ксюше.
3. **Ксюша:** ссылка открывается в Safari → «Создать аккаунт» → «Ваня зовёт тебя» → «Вступить» → открыта группа «Ваня и ты», и при запуске будет открываться она.
   Если приложение у неё уже на экране «Домой»: Safari показывает код, она открывает приложение → Настройки → «Группа» → «Вступить по коду».
4. Теперь у обоих одни блюда, тара и компании; готовый вес, который ввела Ксюша, через минуту (или при открытии приложения) виден у Вани в этом блюде: «Готовый 360 · 19:40».
5. Без сети всё работает; в «Аккаунте» — «Нет сети — изменения сохранены на устройстве». Сеть появилась — «Синхронизировано · 19:42».

## 3. Поведение элементов

- **Полка блюд** (шапка калькулятора, во всю ширину экрана, как шапки других экранов: 🔍 у левого края, где у них «←», «⋯» у правого; на десктопе видны все чипы): 🔍 — одна круглая кнопка в начале, вне прокрутки, с подсказкой при наведении «Найти блюдо ⌘K /»; открывает меню блюд. ⌘K / Ctrl+K и «/» (когда курсор не в поле) открывают его же. Дальше чипы (36 px на вид, 44 px для пальца) по последнему использованию, в начале каждого — иконка категории блюда (16 px, приглушённая; у текущего чипа — цвета текста); текущий обведён, тап по другому открывает его калькулятор. Пока полка открыта, порядок не меняется; новое блюдо встаёт в начало. «⋯» справа.
  - *Что поднимает блюдо в начало* (`updatedAt`, общий для группы): создание («Создать», «Сделать составным», популярное из поиска или «Популярных блюд»), «Сохранить» в редакторе и ввод в калькуляторе того, что блюдо запоминает, — сухой вес, тара, готовый вес; так же — на другом устройстве группы. *Не поднимают:* просто открыть блюдо (чип, меню блюд), скопировать ответ, «Кто ест» и доли — они хранятся отдельно от блюда (`lineups`), и их правка не перезаписывает блюдо, которое в это время меняют на другом устройстве.
  - *Когда полка пересортировывается:* когда открывается калькулятор (запуск, возврат из редактора, меню блюд, настроек) и когда возвращаешься в приложение из фона. Тап по чипам переключает блюда без пересортировки: чип не уезжает из-под пальца. Блюда, появившиеся при открытой полке (добавлено из меню блюд, пришло из группы), встают в начало; удалённые исчезают.
- **Меню блюд** (`#/dishes`, экран во весь экран §3а — на телефоне и на десктопе, палитры поверх нет): заголовок «Блюда», справа в шапке «+» (круглая кнопка 44 px, «Добавить блюдо» → форма; без блюд её нет — в списке большая «Добавить блюдо») и «⋯»; под шапкой поле поиска, ниже один список. Ни фильтра по типу, ни сортировки: порядок задают разделы, «только супы» находятся словом «суп» или «перв».
  - *Поле поиска сразу в фокусе и клавиатура открыта* (iPhone в Safari и установленной PWA, Android, десктоп): сразу печатаем. Поле 16 px, клавиша клавиатуры — «Перейти» (`enterKeyHint="go"`), ✕ в поле очищает его и оставляет фокус. На iPhone клавиатура открывается, только если поле получило фокус прямо в обработчике тапа, поэтому тап по 🔍 сначала фокусирует невидимое поле, которое всегда есть на странице, и уже потом открывает экран — фокус переходит в настоящее поле, клавиатура остаётся.
  - *«По категориям»* — круглая кнопка 40 px с иконкой `ListTree` в конце поля, после ✕ («Очистить», только пока что-то набрано); есть и при наборе; подсказка при наведении и `aria-label` «По категориям», `aria-pressed`. Выключена — прозрачная, иконка приглушена (при наведении приглушённый фон); включена — фон `secondary`, обводка `ring-2` цвета текста, иконка цвета текста. Нажатие не забирает фокус у поля и не прячет клавиатуру (как ✕). Выбор помнится на устройстве. Только в меню блюд, в «Из блюда» кнопки нет. Включена — свои блюда разделами по категориям: заголовок — название категории, справа число блюд (приглушённо, цифры одной ширины), без иконок рядом с названиями; пустые категории не показываются; отдельного «Часто готовишь» нет — порядок «Часто готовишь» внутри раздела; «Добавить из популярных» — плоским списком в конце. С текстом — только категории с совпадениями, первой та, где лучшее совпадение, так что первая строка — лучшее совпадение, и Enter берёт её. Правила — SPEC §3б.
  - *Поиск по категории:* запрос «гарн», «перв», «выпечк» находит блюда этой категории (ниже совпадений по названию и ингредиенту); во второй строке — название категории, подсвеченное. В разделе «По категориям» название категории в строке не повторяется — подсвечен заголовок раздела.
  - *Esc в поле поиска* (и в меню блюд, и в «Из блюда»): пока что-то набрано — очищает поле и оставляет в нём фокус; в пустом поле закрывает экран, как «←».
  - *Иконка в начале строки* (слот 18 px, приглушённая): категория блюда: Первые — суп, Вторые — ножка, Гарниры — колосок, Салаты — салат, Завтраки — яичница, Выпечка и сладкое — кусок торта, Напитки — стакан, Другое — приборы (lucide). Нет её у строки «Создать «…»».
  - *Разделы без текста в поле:* «Часто готовишь» (свои блюда, которыми пользовались в 2 и более разных дней за последние 60, не больше пяти), «Остальные · по алфавиту» (если «Часто готовишь» пусто — «Твои блюда · по алфавиту»), «Добавить из популярных» (каталог «Популярных блюд», которых ещё нет, в порядке каталога). С текстом: «Твои блюда» (лучшие совпадения выше, среди равных — как в «Часто готовишь»), «Добавить из популярных». Порядок и правила — SPEC §3б.
  - *Строка списка* (одна на «Меню блюд» и «Из блюда», 48 px и выше): слева название (16 px, одна строка), справа обычный вес («200 г», 14 px, приглушённый), у блюда из нескольких ингредиентов — сумма сырых; у блюда без веса — пусто. Под названием вторая строка (12 px, приглушённая, одна строка): у блюда из двух и более ингредиентов — ингредиенты без «не учитывать»; у блюда из одного ингредиента — ничего (в «Из блюда» — название ингредиента, если оно отличается от названия блюда: «Куриная грудка» / «Куриное филе»); у блюда без названия второй строки нет (название и есть ингредиенты). Найденное в запросе подсвечено (`<mark>`). Если название не подошло, а ингредиент подошёл (в том числе «Вода» — не учитываемый), он встаёт первым во второй строке и подсвечен — многоточие его не съест.
  - *«+» в конце строки* (круглая отметка 32 px) значит «тап что-то добавит»: у популярных — всегда; у своих блюд в «Меню блюд» его нет, тап открывает калькулятор. Тап по популярному — блюдо создано и сразу открыто, без тоста: открывшееся блюдо и есть результат.
  - *«Создать «Хачапури»»:* пока в поле есть текст и ни у одного своего блюда название не равно ему (без учёта регистра и «ё»), последней строкой — «Создать «Хачапури»» (запрос без пробелов по краям, первая буква заглавная), под ним приглушённое «Откроется форма с этим словом»; название цвета primary, «+» пунктиром. Тап открывает форму «Добавить блюдо» с этим словом в «Что в блюде» и курсором после него (`#/d/new?text=Хачапури`; читается один раз, при открытии формы). Ничего не нашлось — «Ничего не нашлось» и только эта строка, она выделена: Enter создаёт.
  - *С клавиатуры:* Enter («Перейти» на телефоне) открывает выделенную строку — сначала это первая в списке; на десктопе ↑ / ↓ двигают выделение; Esc сначала очищает поле, потом закрывает экран (как «←»).
  - *Адрес* хранит только текст поиска: `#/dishes?q=гре` (пусто — параметров нет; при наборе адрес заменяется, новых записей в истории нет). Старые `kind` и `sort` игнорируются. «Назад» из калькулятора возвращает в то же меню с тем же текстом.
  - *Без блюд* это первый экран (`#/`) — тот же экран и то же поле. Без текста: заголовок «Пока нет блюд», «Добавь блюдо один раз — дальше у плиты вводи только готовый вес.», большая кнопка «Добавить блюдо» на всю ширину, «Или возьми из популярных» — весь каталог строками с «+» и в самом конце «Добавить все N» (кнопка `outline` на всю ширину; без подтверждения: своих блюд нет). С текстом: подходящие популярные и «Создать «…»».
- **«⋯»** (`DropdownMenu`, пункты 44 px) — во всех шапках: действия экрана, разделитель, «Настройки». Калькулятор: «Изменить «Гречка»», «Добавить блюдо». Меню блюд: «Добавить популярные блюда» (пока есть свои блюда и не все популярные добавлены; `AlertDialog` «Добавить популярные блюда?» с числом простых и составных → «Добавить», тост с «Отменить»; блюда с таким же названием пропускаются), «Настройки» («Добавить блюдо» — «+» в шапке). Редактор существующего блюда: «Сделать составным» (у простого), «Удалить блюдо» (красным, `AlertDialog`).
- **Редактор блюда** (вариант «Одной строкой», этап 19): черновик живёт в форме, сохраняется только кнопкой «Создать» / «Сохранить» (неактивна, пока не хватает данных; над ней текст, чего не хватает: «Введи ингредиент», «Проверь разбор: нет названия»). Заголовок — «Добавить блюдо» / «Изменить блюдо». Сверху вниз:
  - *Название* — первое поле, крупно (20 px). Пусто — в поле видно имя по ингредиентам (`dishTitle`), так блюдо и назовётся; справа от подписи «можно не писать».
  - *Категория* — сразу под названием, `Select` без поиска (список из девяти пунктов — экраном не делаем). В поле — название категории и справа тихая пометка «по названию» или «выбрано вручную». Первый пункт — «По названию · <что угадано сейчас>» (категория не хранится, `category: null`), под ним разделитель и восемь категорий в порядке показа, без иконок. Пока выбрано «по названию», поле следит за названием (и за ингредиентами, если название пустое) вживую. Если угадать не вышло («Другое») и что-то набрано, под полем приглушённая строка «По названию не угадать — выбери вручную». Сохраняется вместе с формой («Создать» / «Сохранить»). «Сделать составным» и `?text=` работают как раньше.
  - *Что в блюде* — одно многострочное поле (`Textarea`, 16 px, растёт по тексту): ингредиент и вес через запятую или с новой строки — «курица 600, картофель 400, вода 2 л, соль». Правила разбора — SPEC §7а. Заголовок «Что в блюде ⌄» сворачивает поле (`Collapsible`): остаются заголовок с «Вставить» и «Из блюда», разбор поднимается под него — удобно работать со списком; поле с микрофоном и строки под ним («Слушаю…», «Услышано», «Пропущено», подсказка) скрыты, идущая запись останавливается. При открытии формы поле развёрнуто; свёрнутость не запоминается. Над полем справа «Вставить» (текст из буфера дописывается в конец; без доступа к буферу кнопки нет) и «Из блюда» (экран «Из блюда» — тот же список и та же строка, что в меню блюд, но в режиме выбора: поле «Гречка, рис…», под ним «Блюда из одного ингредиента — добавятся с обычным весом»; разделы «Твои блюда» (простые, по «Часто готовишь») и «Популярные» (простые, которых у вас ещё нет), у каждой строки «+»; тап или Enter дописывает в конец: «Макароны 130» — и возвращает в форму; «Создать» нет, ничего не нашлось — «Ничего не нашлось»). В правом нижнем углу поля — круглая кнопка-микрофон (40 px, область касания 44 px). Курсор при открытии формы — в конце поля.
  - *Голос:* тап по микрофону — запись: кнопка становится «стоп» (основной цвет, мягко пульсирует; при «уменьшить движение» — без пульса), рамка поля синяя, под полем «● Слушаю…» и распознаваемый текст по мере речи. Запись идёт, пока не нажали «стоп»: паузы, чтобы подумать, её не прерывают (браузер сам заканчивает распознавание после тишины — мы тут же продолжаем, сказанное копится); сама она останавливается только после 30 с тишины. По «стопу» всё сказанное приводится к фразе (SPEC §7а) и дописывается в конец поля, без тоста; под полем «Услышано: «…»» (две строки, до следующей правки поля). Сказанное, что не похоже на ингредиент («я вот что-то говорю…»), в поле не попадает: строкой ниже «Пропущено: «…»» (одна строка). Ничего не распознано — тост «Ничего не слышно — попробуй ещё раз». Распознаёт браузер (Web Speech API, язык `ru-RU`). Где распознавания нет (Firefox) — кнопки нет, подсказка под полем без «или голосом». Нет доступа к микрофону — тост «Нет доступа к микрофону — разреши его в настройках браузера». Без сети приложение работает как обычно, отдельного «нет сети» нет; тост «Нет сети — голос сейчас недоступен» — только когда нажали микрофон без сети и браузер не смог распознать (Chrome распознаёт на серверах Google; Safari иногда умеет без сети — тогда тоста нет, голос работает). Надиктованное с клавиатуры телефона (её микрофон) приводится к той же фразе, когда уходим из поля: тост «Приведено к виду «ингредиент вес» · Отменить».
  - *Разбор* — под полем на матовом фоне, подпись «Разбор · тап — учитывать или нет, × — убрать», по строке на ингредиент: название, метка «не в счёт», вес справа («600 г», «≈ 2 000 г» из литров, «2 шт», «ложки», «по вкусу», «без веса»), под ним пометки. Строка, в которой стоит курсор поля, — белая «коробка». Тап по строке — учитывать / не учитывать; курсор и клавиатура остаются в поле. × (виден всегда, и на телефоне: строки разбора — отражение текста, их не смахивают) — вырезает ингредиент из фразы вместе с запятой, тост «Убрано: Курица · Отменить». Пусто — «Здесь появится разбор: ингредиент и вес.»
  - *Пометки* под строкой разбора (12 px, с треугольником): ошибка красным — «Создать» неактивна: «нет названия», «вес 0», «не понял вес»; предупреждение янтарным (`--warning`) — не мешает: «из 2 л: считаем 1 мл ≈ 1 г», «3 шт — нужен вес в граммах», «ложки — нужен вес в граммах», «8 кг — точно?», «2 г — может, это штуки?», ««Гречка» уже есть выше».
  - *Итог* — тихая строка под разбором: «**Простое** · сухой 200 г» / «**Составное** · сырой 1 360 г · не в счёт 2 016 г». Вид следует из ингредиентов (SPEC §3), переключателя нет.
  - *В чём взвешиваете* — ряд чипов (36 px, область касания 44 px), прокручивается вбок целиком, вместе с «+»: первым круглый «+» с пунктирной рамкой («Добавить тару» для экранного диктора) — экран «Новая тара» поверх формы (§3а), вернувшись, новая тара выбрана; дальше «Без тары» и тары с весом серым («Кастрюля 850 г»). Выбранная — белая, обведена, как текущее блюдо на полке.
  - Внизу — одна кнопка «Создать» / «Сохранить» на всю ширину (`BottomBar`); отмена — «←», «Отмены» нет.
- **Плитки калькулятора:** «Сухой» (у составного с несколькими учитываемыми — «Сырой» с суммой и двумя строками: «5 ингредиентов,» / «не в счёт: Вода, Соль» или «без веса: Шампиньоны») и «Готовый» в ряд, всегда одинаково; подпись «Готовый · 19:40», если подставлен сегодняшний расчёт. У «Сырого» тап по телу плитки выбирает сырой вид, круглая кнопка «›» (36 px, зона нажатия 44, `aria-label` «Ингредиенты») в правом верхнем углу открывает экран «Ингредиенты». Под плитками — тара, «без тары · k». Плитка в фокусе задаёт вид порций (SPEC §3б): «Готовый» — граммы людей и полосы готовые, под именем «38 г сухого» («680 г сырого» у составного); «Сухой» / «Сырой» — граммы сухого (сырой суммы), под именем «100 г готового», своя порция вводится в этом виде.
- **Экран «Ингредиенты»** (`#/d/<id>/ingredients`, §3а, только у составного блюда): шапка — «←», «Ингредиенты» и название блюда под ним; сверху «Сырой» и живая сумма учитываемых; карточка строк «название — поле грамм» (`NumberField`, справа, «г»): сначала учитываемые, затем заголовок «Не в счёт» с «в порции не попадают» справа и приглушённые строки; внизу «Блюдо запомнит эти веса. Поменять сам состав — «⋯» → «Изменить блюдо».» Enter — следующее поле. Веса пишутся в блюдо сразу, как на плитках раньше.
- **«Состав»** (SPEC §3б): переключатель (`Toggle`, 44 px) в конце строки «Кто ест», только у составного с несколькими учитываемыми; выключен — контур, включён — фон карточки и внутреннее кольцо 2 px цвета текста, `aria-pressed`. Рецепт «название … граммы» раскрывается за 220 мс (без анимации при reduced motion): названия переносятся до двух строк (полное — в `title`), граммы не переносятся, прижаты вправо. Две колонки, пока все названия блюда короткие; хоть одно длинное — одна колонка везде. У людей — под строкой каждого; в «Долях» — один раз под «по 690 г × 4» при равных порциях, иначе в плитках (своя — на всю строку, при неравных — по две в ряд).
- **Компания в калькуляторе** (`Select` над полосой долей): выбор подставляет людей и доли компании в состав блюда; выбранная компания так и остаётся в поле, когда двигают ползунок или добавляют людей — компания и её название от этого не меняются. Состав и доли запоминаются у каждого блюда отдельно. Последний пункт — «Добавить компанию»: экран «Новая компания» (§3а) открывается, когда список закрылся, фокус в «+ Имя»; форма та же, что в настройках (`CompanyForm`). После «Добавить компанию» — снова калькулятор, новая компания выбрана в поле.
- **«Доли» в списке «Кто ест»** (этап 16, SPEC §3б): пункт после компаний (иконка — круговая диаграмма), до разделителя и действий. Выбран — в поле «Доли», вместо людей безымянные «Порция 1 … Порция 6» с той же полосой и своей порцией (граммы, «Сухой» / «Готовый»). Вместо строк — **ответ одной строкой и сетка контейнеров** (этап 17): сверху «по 80 г × 7 · 29 г сухого» и ⧉ («Скопировать для трекера: одна порция» — у равных порций текст для трекера один), под ним, если есть свои, — «своя: 5 — 120 г»; порции разные (после ползунка) — «73–79 г · 7 порций по долям», ⧉ в строке скрыта, но место за ней остаётся: при переходе «поровну ⇄ по долям» строка не прыгает. Ниже — контейнеры. **Порции, которые делят по долям, равны:** граммов в их контейнерах нет совсем (они сказаны выше один раз) — только номер крупно в крышке (34–40 px, цифры 1,0625–1,25 rem 600) в низкой коробке (~64 px), по четыре в ряд на телефоне; тап по коробке выбирает её (белая коробка с крышкой в кольце), тап по уже выбранной открывает поле своей порции (коробка становится белой с полем граммов, в подсказке — сегодняшние граммы), как набор числа в контейнере. Своя порция среди них — контейнер во всю строку с граммами (и рецептом в «Составе»). Сначала идут контейнеры порций, которые делят по долям, свои — после них, как на полосе; номер у каждой свой, по месту. **Порции разные:** контейнеры по три в ряд (по два уже 360 px, по четыре с `lg`): номер в метке-крышке, число крупно (тап по числу — своя порция, как у человека; тап мимо поля выбирает контейнер), под ним сухой вес (в «Сухом» — готовый). До взвешивания в контейнере только крупный номер порции, строки ответа нет. ⧉ у контейнера — когда порции разные и у своей; у равных копирует строка ответа, а у контейнеров ⧉ скрыта, высота та же. Своя порция — пунктирная рамка, как её сегмент на полосе; «своя ×» в контейнере нет (на троих в ряд места хватает одной кнопке): стёртое число возвращает порцию к доле, «Сбросить свои» — все сразу. Свайпов в сетке нет: порции нумеруются по месту, поэтому «−» рядом с «Доли» и есть «убрать порцию». Имя у порции не правится. На сегментах полосы — только номер порции («3», без граммов) вместо «Порция 3»: он помещается и в узкий сегмент, где имя уже пропало бы, и различает порции, когда их больше, чем крышек. «На завтра» нет. Число порций — в той же строке, справа от поля «Доли»: «− 6 +» (`ButtonGroup`, 44 px; «−» неактивна на 1, «+» — на 100), полоса под ними — во всю ширину. Под полосой — «− ■ +» для выбранной порции, как у людей: между кнопками её крышка с номером (28 px); сначала первой (обведена, ручки по её краям — поэтому ручки есть всегда), тап по сегменту или по контейнеру выбирает другую. Строки «+ Имя» внизу списка нет, список кончается последней порцией. «Сохранить состав как компанию» в режиме долей не показывается. Чтобы вернуться к людям — выбрать компанию; если у блюда был свой состав без компании, в режиме долей в списке есть пункт «Свой состав · 4» — он возвращает этот состав. Режим и порции — на этом устройстве для всех блюд.
- **Новая тара** — одна форма везде (настройки, экран «Новая тара» из калькулятора), крупная: «Название» и «Вес» друг под другом, поля высотой 56 px с текстом 18 px, вес — только числом в поле (ползунка нет); кнопка «Добавить тару» обычного размера (44 px) справа под полями — на экране «Новая тара» она не больше главной кнопки «Готово» внизу; неактивна, пока нет названия и веса больше 0. Enter в «Название» переводит в «Вес», Enter в «Весе» добавляет тару. **Несколько тар за раз:** после добавления форма очищается, фокус снова в «Название» (клавиатура телефона не прячется) — сразу вводится следующая. В настройках новая тара сразу видна строкой в списке над формой; на экране «Новая тара» — в списке «Добавлено» над формой («Миска · 320 г», у выбранной — галочка), экран открыт, пока не нажали «Готово» или «←».
- **Компании в настройках:** правятся на месте тем же интерфейсом, что «Кто ест» в калькуляторе (SPEC §3б): название, полоса долей (тянуть границы, «− Ваня +», «Поровну»; без «На завтра» и без чисел — блюда здесь нет, часть видна шириной сегмента), под ней люди (имя · × удержанием, как в калькуляторе), внизу поле «+ Имя» (Enter — человек добавлен с долей, средней по остальным, поле готово для следующего). Новая компания открывается пустой, с фокусом в «+ Имя». Удаление компании — с тостом «Отменить».
- **Копирование:** тост «Скопировано» с первой строкой текста; без доступа к буферу — экран с выделенным текстом (§3а).
- **Свайпы строк (телефон и iPad):** устройство определяем по вводу (`pointer: coarse`), а не по ширине — iPad тоже получает свайпы. Строка едет за пальцем, под ней проступает действие: свайп влево — красное «Убрать», свайп вправо — «Копировать». Отпустил после короткого свайпа (от 48 px) или быстрого взмаха — строка доезжает и остаётся открытой на действии (тап по нему — сделать, тап по строке — закрыть; взмах обратно — закрыть); свайп на полстроки и дальше — действие сразу. Взмах сам по себе действие не делает — только расстояние. Открыта только одна строка: начал свайп или тапнул по другой — открытая закрывается. Вертикальная прокрутка свайп не запускает. Удаление свайпом — с тостом «Убрано: Ваня · Отменить» (у ингредиента — «Убрано: Курица · Отменить»). Иконки ⧉ и × на сенсорном экране скрыты, но остаются для клавиатуры и экранного диктора. С мышью и трекпадом (десктоп) — иконки, как раньше, свайпов нет.
  - **Анимации.** Под пальцем строка едет 1:1, без задержки; за краем (вправо у строки без «Копировать», дальше ширины строки) — тянется с сопротивлением. Отпустил — строка доезжает за 150–250 мс с замедлением в конце, тем быстрее, чем быстрее был взмах. Действие под строкой проявляется и подрастает по мере свайпа, а когда отпускание уже сделает действие — чуть увеличивается. Удаление (полный свайп, тап по «Убрать», × на десктопе): строка уезжает влево, потом её высота плавно схлопывается и строки ниже поднимаются, без скачка; «Отменить» — строка возвращается на место, раскрываясь по высоте с проявлением (≈200 мс).
  - **Меньше движения** (`prefers-reduced-motion: reduce`): строка под пальцем по-прежнему едет, но все переходы мгновенные — без доезда, уезжания, схлопывания и раскрытия.
  - Человек в калькуляторе: влево — убрать из сегодняшнего состава, вправо — скопировать для трекера. На десктопе × по-прежнему удержанием; удержал — строка уезжает и схлопывается так же, как после свайпа.
  - Порции в «Доли» — сетка без свайпов (§3, этап 17): «−» рядом с «Доли» убирает последнюю, ⧉ в контейнере или в строке ответа копирует.
  - Тара в настройках: только влево — удалить. Строки разбора в редакторе блюда не смахиваются: × у них виден всегда (этап 19).
  - Участники группы: × удержанием и на телефоне — удаление идёт на сервер, вернуть тостом нельзя.
- **Удаление** блюда — «⋯» редактора → «Удалить блюдо» → `AlertDialog`; вместе с ним уходит его состав «Кто ест».
- **Ошибки ввода** — под полем, красным, текстом.

- **Компоновка (после /impeccable adapt distill):** без карточек — секции с заголовками и отступами; главная кнопка экрана («Создать / Сохранить») на телефоне прилипает к низу под большой палец, на десктопе стоит сразу после основного содержимого. На телефоне «назад» в шапке — только стрелка. В калькуляторе «Сухой» и «Готовый» в одном ряду, под ними одна тихая строка «Без тары · k = 2,4»; у человека имя и сухой вес слева, готовый вес крупно справа.

- **Цвета едоков:** у каждого человека из сегодняшнего состава свой цвет крышки (небо, подсолнух, мята, сирень, абрикос, бирюза, роза, фисташка, лаванда, пион — десять, чтобы хватило на meal prep на 10 дней; с одиннадцатого — по кругу). Им окрашены его сегмент в полосе долей (48 px, имя и под ним граммы; между полосой и «− Ваня +» 12 px) и метка у имени. Своя порция в граммах — та же крышка бледнее, с пунктирной рамкой; в тёмной теме — крышка контуром: фон почти ночной, число и пунктир цвета крышки (бледная крышка на ночном фоне выходила грязно-коричневой). Выбранный для «±1 %» — обведён, цвет сохраняется. Ручки на границах — там, где соседям хватает места (сегменты от 4 rem); у краёв выбранного (сначала — первого) — всегда, поэтому при 6–7 порциях на телефоне полоса показывает граммы, а ручки есть у выбранного сегмента; тап по другому переносит их. Где ручки помещаются, решает ширина полосы с шагом 2 rem и запасом на погрешность: равные порции получают ручки все вместе или ни одна. Различие дублируется именем, не только цветом.
- **Курсор калькулятора** — системный курсор поля; его цвет примерно с каждым миганием переходит на крышку следующего едока. Без людей и при «уменьшить движение» — основной цвет.
- **Поля калькулятора** не похожи на поля ввода: число без рамки, шириной по себе, «г» сразу за ним. Поле в фокусе — белая «коробка» с рамкой на матовом фоне.

## 3а. Экраны и окна поверх

Правило для всех экранов, новых и существующих (2026-10-06).

**Где много контента — отдельный экран во весь экран.** Много — это поле ввода, поиск, список с прокруткой или больше пары строк текста. Сюда относятся создание и правка (блюдо, тара, компания), вход, «Вступить по коду», поиск (меню блюд), выбор из списка с поиском («Из блюда»), показ текста для копирования. Для них не используем `Dialog`, `Sheet`, `Drawer` или `Popover`.

Такой экран:
- **во весь экран телефона:** шапка с «←» (на телефоне только стрелка) и заголовком — что делаем («Новая тара», «Вступить по коду»), главная кнопка внизу (`BottomBar`), с учётом выреза и полоски «Домой»;
- **со своим адресом** `#/…`: системный «назад» (свайп от края на iPhone, кнопка «назад» на Android и в браузере) работает так же, как «←», после перезагрузки открывается тот же экран. Поиску и выбору из списка адрес не обязателен, но системный «назад» должен их закрывать;
- **возвращает в то же состояние.** «←» и системный «назад» ведут ровно туда, откуда экран открыли: тот же экран, то же блюдо, тот же подраздел, та же прокрутка, те же раскрытые блоки. Черновик не сохраняется, как в редакторе блюда;
- **после главной кнопки** («Готово» на экране «Новая тара», «Добавить компанию») — тоже назад, и результат уже на месте: тара выбрана у блюда, компания — в поле компании, фокус на поле, из которого открывали. Заполненная форма уходит из истории: системный «назад» на неё не возвращает. Исключение — «Создать» в редакторе блюда: открывается калькулятор нового блюда. На экране «Новая тара» «Добавить тару» с экрана не уводит — можно добавить несколько подряд (§3), назад ведёт «Готово»;
- **фокус** — в первом поле;
- **переход анимируется:** вглубь и назад — в разные стороны; при «уменьшить движение» — без анимации (§1 «Переходы между экранами»).

**Открытие из списка или меню.** Пункт, который открывает экран («Добавить тару», «Добавить компанию»), — последний в списке, после разделителя, с «+»: он выглядит как действие, а не как значение. По тапу сначала закрывается список (`Select`, `DropdownMenu`, `Popover`), значение поля не меняется, потом открывается экран. При возврате фокус — на поле, из которого открывали.

**Поверх экрана — только короткое:**
- подтверждение — `AlertDialog`: вопрос, одна-две строки пояснения, две кнопки («Удалить блюдо?», «Перенести данные этого устройства?»). Так же устроены подтверждения в iOS и Android;
- меню «⋯» (`DropdownMenu`) и выбор из списка без поиска и без полей (`Select`);
- подсказки (`Tooltip`) и тосты (`Sonner`).

Если в окне понадобилось поле ввода, поиск или прокрутка — это уже экран.

**Тосты — редко.** Тост сообщает о том, что случилось, но не видно на экране: фоновое событие («Есть новая версия», «Ты больше не в группе…», «Нет сети…»), ошибка, которой негде встать рядом с полем, или «Отменить» после удаления и массового действия («Убрано: Ваня», «Тара удалена», «Блюда добавлены» после «Добавить все»). Если результат тапа и так виден сразу — открылся экран, появилась или пропала строка, поменялось поле, — тоста нет. Так, после тапа по популярному блюду нет «Блюдо добавлено»: блюдо уже открыто.

**Планшет и десктоп (с `md`).** Формы — те же экраны по тем же адресам, одна колонка ≤ 720 px по центру, как редактор блюда. Меню блюд — тоже экран и на десктопе (⌘K открывает его, палитры поверх нет).

Экран поверх другого — его дочерний адрес (`#/d/<id>/tare/new`): экран под ним остаётся открытым, только спрятан, поэтому «назад» возвращает его как было — те же введённые числа, свои порции, черновик. Переход тот же, что между экранами (§1 «Переходы между экранами»): экран поверх въезжает справа, при «назад» экран под ним — слева. «Из простого блюда» — экран на всех ширинах.

## 3б. Подсказки для новых (этап 18)

Макеты — [mockups/onboarding-hints.html](mockups/onboarding-hints.html), план — [этап 18](roadmap/18-onboarding-hints.md).

**Тур по калькулятору.** Показывается при первом открытии калькулятора на этом устройстве, одинаково на телефоне и на десктопе.
- Экран темнеет, виден один элемент. Рядом карточка: заголовок, текст, «1 из 4», «Пропустить», «Далее»; на последнем шаге — только «Готово».
- Шаги:
  1. плитки «Сухой | Готовый» (у составного — «Сырой | Готовый»);
  2. тара «Без тары ⌄»;
  3. «Кто ест»: без людей — список и «+ Имя», с людьми — полоса долей;
  4. полка блюд.
- Тур начинается через полсекунды после открытия калькулятора, когда сверху нет тостов («Блюда добавлены · Отменить» закрыл бы шаги). На сенсорном экране — ещё и когда закрыта клавиатура.
- Тап по затемнению — «Далее», ← / → листают. Выделенный элемент во время тура не нажимается.
- **«Пропустить»** (и Esc) выключает подсказки. Появляется тост «Подсказки выключены · Вернуть»; «Вернуть» продолжает тур с того же шага.
- **Уход с экрана** (системный «назад», ссылка) закрывает тур. При следующем открытии калькулятора он продолжится с того же шага. Записей в истории тур не добавляет.

**Подсказок по месту нет.** Карточки в потоке (вид C: «Скопировать для трекера», «Добавь на экран „Домой“») сделали и убрали 2026-10-07 — не понравились. Только тур.

**Цвета.** Тур — основного цвета и нейтральные. Цвета крышек в нём не используются.

**Кто уже пользуется.** Если при первом запуске этой версии на устройстве уже есть блюда, приветствие и тур считаются пройденными.

Что показано и пропущено — настройка устройства, как тема: в группу и в копию данных не попадает. Вернуть — Настройки → Подсказки (на телефоне — прямо в хабе, с `md` — в «Оформлении»).

## 3в. Приветственный экран (этап 18)

`#/welcome` — экран во весь экран (§3а). Открывается с `#/`, когда на устройстве нет блюд и приветствие не пройдено. По прямой ссылке открывается всегда: если приветствие уже пройдено — уводит на `#/`.

- **Шапка:** точки шагов слева и «Пропустить» справа — на каждом шаге, и на «Аккаунте» тоже. С любого шага сразу в приложение без аккаунта, как «Без аккаунта» (2026-10-07).
- **Внизу** (`BottomBar`) — «Далее». Шаги внутри экрана, адрес один; «назад» с приветствия — туда, откуда пришли.
- **Листать шаги** (2026-10-07). Сенсорный экран (`pointer: coarse`): свайп влево — следующий шаг, вправо — предыдущий (от 48 px или быстрым взмахом); вертикальная прокрутка свайп не запускает; на последнем шаге свайп влево ничего не делает — оттуда только кнопками. Точки шагов здесь только показывают, где ты. Мышь и клавиатура: точки — кнопки («Шаг 2 из 4»), клик открывает этот шаг; ← / → листают. Шаг вперёд въезжает справа, назад — слева; при «уменьшить движение» — только появляется.
- **Шаги** — у каждого иллюстрация из логотипа (ланчбоксы с крышками) с простой анимацией. При «уменьшить движение» — без анимации.
  1. «Сколько положить каждому» — что делает приложение. Ланчбоксы падают в стопку, крышка встаёт к стопке.
  2. «Блюдо помнит всё» — сухой вес, тара, кто ест; у плиты — одно число. Плитки «Сухой 200 г | Готовый 560 г», готовый вес появляется.
  3. «Поровну или по долям» — доли, «На завтра», «Доли» для порций на неделю, копирование в трекер. Полоса долей, граница ходит.
  4. «Аккаунт или это устройство» — что даёт аккаунт и что будет без него. «Создать аккаунт» — `#/account?tab=sign-up` (после регистрации — `#/`); «Без аккаунта» — на `#/`; ссылка «Уже есть аккаунт? Войти» — `#/account`. Кто уже вошёл, этого шага не видит: на третьем — «Начать».
- **Приветствие пройдено** после «Пропустить», «Без аккаунта», «Начать», «Создать аккаунт» и «Войти». «Назад» со входа на него не возвращает.

### Настройки
Разбиты на подразделы, у каждого свой адрес `#/settings/<подраздел>` (назад/вперёд и перезагрузка возвращают туда же):

Подразделы собраны в три блока, чтобы «Группа» (с кем общие данные) и «Компании» (кто ест и в каких долях) не стояли рядом: аккаунт со своей группой; «Кухня»; «Приложение».

|---|---|---|---|

Вошли — профиль (фото, имя, фамилия, короткое имя), статус синхронизации (этап 13), passkey, «Выйти» (только с сетью; данные групп уходят с устройства, на сервере остаются) — см. «Аккаунт и группа» ниже |

**Телефон (< 768 px):** `#/settings` — хаб: всё настроенное читается, не открывая подразделов.

Не вошли — «Блюда только на этом устройстве», «Войди — они будут на всех твоих устройствах, и ими можно поделиться с близкими.», большая «Войти» → `#/account`. Вошли — строка аккаунта (фото или инициалы, имя, почта, статус синхронизации одной строкой; «Войти снова» — уже внутри «Аккаунта») и строка открытой группы: фото участников, её название («Ваня и ты») и «Группа: общие блюда, тара и компании»; пока в ней только ты и других групп нет — «Только ты» и «Группа. ### Вход (`#/account`, этап 12)
```
│ ←  Аккаунт                          │
│ [ Войти | Создать аккаунт ]         │
│ Почта   [ vanya@example.com       ] │
│ Пароль  [ ••••••••                ] │
│ [            Войти              ]   │

│ Не помнишь пароль?                      │
```
- Поля: `autocomplete="email"`, `"current-password"` / `"new-password"` — iPhone предлагает и сохраняет пароль. В поле почты iPhone сам предлагает passkey (Face ID), если он уже добавлен.
- Без сети: после нажатия «Войти» — «Нет сети — войти можно, когда она появится».
- «Не помнишь пароль?» (пока нет писем): нужна почта в поле; под полями — «Ссылку для нового пароля пришлёт владелец приложения — напиши ему». По ссылке — экран «Новый пароль» (`#/account/reset`) → «Сохранить пароль» → тост «Пароль изменён — войди с ним».
- Ошибки — под полем пароля, свои, по-русски (подсказки браузера выключены): «Минимум 8 символов», «Неверная почта или пароль», «Такая почта уже зарегистрирована», «Нет сети — войти можно, когда она появится», «Passkey не сработал — войди паролем».
- После входа — в Настройки → «Аккаунт». Данные, которые были на устройстве без аккаунта, переезжают в его группу: молча, если в ней пусто; иначе `AlertDialog` «Перенести данные этого устройства?» → «Перенести» / «Не переносить». Копия данных устройства в любом случае остаётся в браузере.

│ ┌──────────────────────────────┐ │ │ С кем у тебя общие блюда…    │ │ ←  Ваня и ты                 │

**Аккаунт.**
- Сверху карточка профиля: фото 96 px (без фото — инициалы на `secondary`) с круглой меткой камеры, под ним полное имя (без имени — короткое), строка «короткое имя · почта», статус синхронизации.
- Тап по фото: без фото — сразу системный выбор снимка; с фото — меню «Выбрать другое фото» / «Убрать фото» (тост «Фото убрано»). Выбранный снимок открывает экран «Фото» `#/settings/account/photo` (§3а, настройки остаются под ним): «Подвинь и увеличь, чтобы лицо было в круге.», квадратное поле со снимком под круглым окном (вне круга снимок уходит под матовый фон), пальцами — двигать и масштабировать, ниже ползунок масштаба (− / +). Внизу «Отмена» / «Сохранить» («Сохраняем…»): квадрат режется на телефоне до 256×256 JPEG и уходит на сервер, экран закрывается. Без снимка (адрес набран руками, перезагрузка) — обратно в «Аккаунт». Не фото — тост «Это не фото — выбери снимок из галереи».
- «О себе» — «Имя», «Фамилия», «Короткое имя» с подсказкой «Так тебя видят в группе. Пусто — vanya». Всё необязательно, сохраняется при уходе из поля (Enter — «Готово»), ошибка — тостом, поле возвращается.
- «Вход» — passkey строками, «Добавить passkey» («Вход по Face ID или отпечатку на этом устройстве») и «Выйти».

**Группа.** Группа называется по людям, с точки зрения того, кто смотрит (`groupLabel`): «Только ты», у Вани — «Ты и Ксю», у Ксюши та же группа — «Ваня и ты»; людей больше трёх — «Ваня, ты и ещё 2». Владелец первым, смотрящий — «ты», имена в именительном (склонять нечего). Если владелец дал группе название («Дом»), показывается оно, а люди — строкой под ним. Группа, которую аккаунт получает при регистрации, хранится как «Личная», и это значит «без названия» (`customName`): «Личная» в интерфейсе не появляется нигде.
- `#/settings/group` — вверху что это: «С кем у тебя общие блюда, тара и компании: что поправит один, через минуту увидят все. Кто сколько ест — в Компаниях». Ниже «Твои группы» — строки со стрелкой: фото участников внахлёст (до трёх, дальше «+N»), название, у открытой — метка «Открыта» (если групп больше одной). В списке ничего не раскрывается: строка ведёт на экран группы. Отдельной коробкой — «Создать группу» и «Вступить по коду» (свои экраны; при трёх группах — тост про лимит).
- **Экран группы** `#/settings/group/<id>` (§3а, настройки остаются под ним; заголовок — название группы, «←» — к списку). Сверху, если групп больше одной: у открытой — «✓ Открыта: её блюда сейчас на экране и откроются при запуске», у другой — «Сейчас открыта другая: Только ты» и внизу под пальцем большая «Открыть эту группу». Открыть — значит и на экране сейчас, и при следующем запуске: это одно действие, звезды и отдельного «Открывать при запуске» нет. Без тоста: кнопка уходит, строка сверху меняется. Ниже:
  - «Название» (только владелец): заглушка в поле — название по людям («Ты и Ксю»), под полем «Пусто — группа называется по людям. Название видят все в группе»; сохраняется при уходе из поля, пустое — снова по людям.
  - «Участники» — фото, короткое имя (своё — «· ты»), под ним полное имя или почта и «владелец»; у владельца × удержанием убирает человека. Последняя строка — «Пригласить» («Код или ссылка для мессенджера»): раскрывает на месте «Код приглашения» крупно (`K7MR-Q2XD`, моноширинные цифры), ссылку, «Копировать» и «Поделиться», «Действует до 13 окт.», у владельца — «Отозвать». Текст для «Поделиться»: «Давай вести блюда вместе в «Порциях»: код …» (с названием — «Вступай в группу «Дом» в «Порциях»: код …»).
  - «Выйти из группы» — отдельной строкой, красным (только в чужой группе), с подтверждением «Выйти из группы «Ваня и ты»?».
  - Группа, в которой человек больше не состоит (адрес набран руками, вышел), — обратно к списку.
- «Вступить по коду» открывает экран с полем кода (§3а), «Проверить» — экран «Вступить в группу».
- Passkey — все ключи аккаунта со всех устройств: имя — менеджер паролей, в котором ключ хранится (iCloud Keychain, Google Password Manager, Windows Hello…), если не узнал — «Passkey»; под ним «Добавлен 7 окт.». «Удалить» → `AlertDialog` «Удалить passkey «iCloud Keychain»?» / «Войти с ним больше не получится. Пароль и другие passkey останутся.» → «Удалить».
- Статус синхронизации — одной строкой под почтой. Если нужно действие («Войди снова…» — с кнопкой «Войти снова», «Обнови приложение…», «Нет доступа к группе»), на «⋯» и пункте «Настройки» — точка цвета `--warning`. «Нет сети…» — обычный режим, без точки.
- «Выйти» из аккаунта: если не всё отправлено — «Не все изменения отправлены. Выйти всё равно?».

### Вступить по ссылке (`#/join/:code`, этап 14)
```
│ Вступить в группу                   │
│ Ваня зовёт тебя                     │
│ Блюда, тара и компании станут общими│
│ [          Вступить           ]     │
│ ─────────────────────────────────── │
│ Приложение уже на экране «Домой»?   │
│ Открой его: Настройки → Группа →  │
│ Вступить по коду                    │
│            K7MR-Q2XD                │
```
- У группы с названием — «Дом» крупно и «Пригласил: Ваня»; без названия — «Ваня зовёт тебя» и «Блюда, тара и компании станут общими» (имя — короткое имя пригласившего, без него часть почты до @).
- «Вступить» — группа сразу открывается, и при запуске тоже (вопроса «Открывать при запуске?» нет), приложение переходит на калькулятор. «Ты уже в этой группе — открыть» — так же.
- Не вошли — вместо «Вступить» кнопка «Войти, чтобы вступить», после входа — снова сюда.
- Нижний блок с кодом — только в браузере, в установленном приложении его нет.
- Код устарел или отозван — «Код не найден или устарел. Попроси новый».

## 5. Десктоп (≥ 1024 px, `lg`)

Калькулятор — одна колонка ≤ 28rem по центру; курсор сразу в первом пустом поле, Enter или ↓ — следующее поле, ⌘K и «/» — меню блюд. Меню блюд и редактор — одна колонка шириной ≤ 720 px по центру; настройки — меню подразделов слева и выбранный подраздел справа (уже с `md`, см. «Настройки» выше).

## 6. Тексты интерфейса (словарь)

Правила текстов:

- На «ты»: «Введи», «Войди», «твои блюда». Не «вы».
- «Ингредиент» везде, не «продукт». Буква `k` остаётся.
- «Убрать» — часть из набора (человек, порция, ингредиент, участник группы). «Удалить» — сущность целиком (блюдо, тара, компания).
- Видимый текст и тултип кнопки рядом с элементом не повторяют его имя: «Убрать», а не «Убрать: Ваня». В `aria-label` имя есть, для скринридера: «Убрать: Ваня» (с двоеточием, потому что имя вводит пользователь и склонить его нельзя). Тост после действия может назвать, что убрано.
- Путь по настройкам пишем без кавычек: Настройки → Группа.
- Ошибки: на каждую причину свой текст, общего «Не получилось» нет. Каждый текст говорит, что случилось и что делать.
