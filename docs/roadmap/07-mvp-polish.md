# 07 — Полировка и проверка гипотезы

## Цель
Довести MVP до состояния, когда им реально удобно пользоваться у плиты несколько дней подряд, и собрать наблюдения для решения «что дальше» из бэклога.

## Зависимости
05 (06 — желательно).

## Задачи
- [ ] Пройти все потоки UX §2 на реальном телефоне (за пользователем; шаблон и наблюдения из разработки — в `mvp-notes.md`) (`pnpm dev --host`) и записать трения в `docs/roadmap/mvp-notes.md`.
- [x] Порядок фокуса и Enter: от поля к полю без лишних тапов (ингредиенты → вес → порции).
- [x] Размеры: все интерактивные элементы ≥ 44 px, поля ≥ 16 px, контраст текста состояний достаточный.
- [x] Доступность: `label` у каждого поля, состояния сверки не только цветом, `aria-live` на плашке сверки.
- [x] Тост «Удалено · Отменить» (`Sonner` с action) для ингредиента и порции.
- [x] Пустые состояния и подсказки по тексту UX §3.
- [x] Ревизия текстов на соответствие словарю UX §6 и запрету «нетто/брутто».
- [x] Обновить SPEC/ARCHITECTURE/UX под фактическую реализацию.
- [ ] По итогам реального использования — пересортировать `backlog.md` (что всплыло при реальном использовании).

## Файлы
Точечно по `src/screens/**`, `src/components/**`, `src/index.css`; `docs/**`; новый `docs/roadmap/mvp-notes.md`.

Lighthouse accessibility (mobile, snapshot): список, готовка с двумя этапами, настройки — 100. SEO-замечание про `robots.txt` относится к dev-серверу.

## Definition of Done
- Все эталонные примеры SPEC §11 проходятся руками без расхождений.
- Минимум три реальные готовки сделаны в приложении, наблюдения записаны.
- Документы соответствуют коду.
- lint/test/build проходят.

## Способ проверки
- Реальный телефон + десктоп-браузер, 375 px и ≥ 1280 px.
- Lighthouse (accessibility) в Chrome DevTools — без критичных замечаний.
- Чек-лист из CLAUDE.md «Как проверять UI».
