# 13 — Синхронизация (offline first)

## Цель
Данные группы хранятся на сервере, а работа идёт с локальной копией. Блюда, готовки, тара, компании, составы и «Убрать человека» видны на всех устройствах, где выполнен вход. Без сети всё работает как раньше: правки копятся на устройстве и уходят на сервер, когда сеть появилась. В этом этапе у каждого одна группа — «Личная», общие группы — в этапе 14.

## Зависимости
12.

## Решения пользователя
- Своя синхронизация, без готового движка: Zustand и IndexedDB остаются локальной базой, сервер — простая таблица записей (ARCHITECTURE §10).
- Конфликт решается по записи целиком: побеждает правка, которая пришла на сервер последней (SPEC §13).
- Вход необязателен. При первом входе локальные данные переезжают в группу.

**Вход и выход**

## Definition of Done
- Два устройства под одним аккаунтом видят одни и те же блюда, готовки, тару, компании и составы; правка доходит за ≤ 60 с, а при переключении на приложение — сразу.
- Без сети приложение работает как раньше; правки, сделанные без сети, доходят после её появления и не теряются при перезапуске.
- Одновременные правки разного не мешают друг другу; правки одной записи сходятся к одному результату на всех устройствах.
- Первый вход переносит локальные данные; выход очищает устройство.
- Эталонные примеры SPEC §11 не изменились; тесты `src/sync` и миграции v10 зелёные; `pnpm lint && pnpm test && pnpm build` проходят.

## Способ проверки
- Chrome и Safari на десктопе под одним аккаунтом: в Chrome создать «Гречку» (пример 1 SPEC §11), в Safari открыть приложение → блюдо на месте. В Safari сохранить готовку с весом с тарой 1410 → в Chrome «История» → готовка с 560 г и k = 2,8.
- Chrome DevTools → Network → Offline: удалить тару, переименовать компанию, сохранить готовку → статус «Нет сети…» → перезагрузка (правки на месте) → Online → «Синхронизировано» → в Safari всё видно.
- Конфликт: оба браузера offline, в Chrome у готовки 3 порции, в Safari её удалить → Safari online, потом Chrome online → у обоих порции на месте (пришла позже). Повторить в обратном порядке → удалена у обоих.
- Первый вход: без аккаунта создать два блюда → «Создать аккаунт» → блюда на месте → войти тем же аккаунтом во втором браузере → блюда пришли. Второй браузер с локальным блюдом → вход → диалог «Перенести…».
- iPhone (установленное приложение, рабочий адрес): авиарежим → гречка, пример 3 SPEC §11 (перевзвешивание 310 → k остатка = 2,58) → сеть → на десктопе та же готовка с двумя этапами.
- `pnpm wrangler d1 execute split-the-portion --remote --command "select type, count(*) from record group by type"` — записи есть, производных значений (k, остатков) в `data` нет.

## Проверено
Тесты: 257, из них синхронизации — 39 (чистые функции, движок, сервер и два телефона на настоящей локальной D1).

Вручную, `pnpm dev` (воркер и D1 внутри Vite), два «устройства» — `localhost` и `second.localhost` (разные origin, у каждого своё хранилище):
- перезагрузка с тестовым аккаунтом → группа «Личная» открыта, «Синхронизировано · 14:11»;
- первое: «Кастрюля 3 л» 850 г → через ~2 с в D1 запись `tare` с `seq` 1;
- второе без входа: «Добавить популярные блюда» (53) → «Войти» → диалог «Перенести данные этого устройства? … блюд: 53 … В группе «Личная» уже есть свои» → «Перенести» → в D1 53 блюда; первое после перезапуска показывает их;
- сервер остановлен → на первом гречка 200 г, 560 г → «Сохранить в историю» → «Нет сети — изменения сохранены на устройстве», готовка в outbox (IndexedDB) → сервер обратно, перезапуск → готовка в D1 (200 → 560) → второе в «Истории»: «200 г сухого · 560 г готового · k 2,8» (пример 1 SPEC §11);
- второе «Выйти» → ключи группы и outbox удалены, локальные данные пустые, копия от входа осталась.

Опрос раз в минуту и «возврат на экран» срабатывают только у видимой страницы: в скрытой панели браузера их не проверить, проверены перезапуском и тестом движка.
