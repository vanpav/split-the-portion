# Бэклог

Приоритеты: **P1** — первые кандидаты после MVP, **P2** — если гипотеза подтвердилась, **P3** — идеи на подумать. Порядок внутри приоритета — по ценности/стоимости.

## P1 — удобство у плиты и доступ с телефона

| Идея | Заметки |
|---|---|
| **Арифметика в поле** (`1240+35`, `1410-850`) | Только `+` и `-`, без скобок; результат под полем. Разбор — доменная логика с тестами, но сначала спросить про готовый парсер выражений |
| **Wake Lock** | Пока открыт экран готовки; тумблер в шапке; только HTTPS. Библиотеку согласовать (ARCHITECTURE §8) |

## P2 — данные и аналитика

| Идея | Заметки |
|---|---|
| **КБЖУ (ручной ввод)** | ккал/Б/Ж/У на 100 г сырого у ингредиента; личный справочник продуктов (автодополнение по названию). Формулы: `ккал блюда = Σ raw_i × ккал_i / 100`, `на 100 г готового = ккал блюда / W × 100`. Ограничение: вытопившийся жир и масло в сковороде завышают калорийность |
| **Средняя k по истории** | «Твоя гречка обычно 2,7». Истории нет с этапа 15: понадобится хранить хотя бы k последних расчётов в блюде |
| **Планирование** | «Хочу 300 г готового риса» → сколько сухого, по средней k |
| **Оценка без взвешивания** | Справочник типичных k (крупы, паста, мясо) для случая, когда готовое не взвешивали; явно помечать результат как оценку |
| **Поделиться по ссылке** | Состояние готовки в URL-хеше (сжатие, например `lz-string` — обосновать); импорт как новой готовки |
| **Кнопка «Остаток» на любой строке** | Если на практике нужно не только у последнего |
| **Meal prep с тарой контейнеров** | Порция = контейнер из библиотеки, ввод веса с тарой |
| **Тёмная тема** | `prefers-color-scheme`, токены уже есть |

## После этапов 11–14: аккаунты и синхронизация

| Идея | Заметки |
|---|---|
| **Письма: сброс пароля и подтверждение почты** | Нужны свой домен и отправка: Cloudflare Email Sending (Workers Paid) или Resend. До этого ссылка сброса — в логе воркера ([CLOUDFLARE.md §10, §13](../CLOUDFLARE.md#13-письма-позже-подтверждение-почты-сброс-пароля)) |
| **Обновления в реальном времени** | Durable Object на группу + WebSocket: правка Ксюши видна Ване сразу, без 60-секундного опроса |
| **Слияние правок блюда по полям** | Сейчас побеждает блюдо целиком, пришедшее позже (SPEC §13): Ксюша вводит готовый вес, Ваня в это время правит рецепт — одно из двух потеряется. Если так бывает — сливать `cooked`, ингредиенты и название отдельно |
| **Убрать записи `cooking` на сервере** | После этапа 15 их никто не читает. Когда старых версий приложения не останется: удалить строки `record` с `type = 'cooking'` и тип из `RECORD_TYPES` |
| **Перевзвешивание** | Убрано из интерфейса на этапе 15 вместе с экраном готовки; модель и тесты в домене остались. Вернуть в калькулятор, если понадобится. «Разделить на N» вернулось как «Режим порций» (этап 16) |
| **Скопировать блюда из другой группы** | «Личная» → общая: блюда, тара, компании одним действием |
| **Удаление группы** | Владелец удаляет группу со всеми данными; сейчас — только выйти или убрать участников |
| **Несколько вкладок на десктопе** | Вкладки не знают о правках друг друга и могут перезаписать IndexedDB; `BroadcastChannel` или `storage`-событие → `rehydrate` |
| **Вход через Google / Apple** | Если почта с паролем окажется неудобной. В установленной PWA на iOS OAuth-редирект уходит в Safari — проверить заранее |

## P3 — на подумать

| Идея | Заметки |
|---|---|
| **Open Food Facts** | Поиск и штрихкод для КБЖУ. Внешний API — только после проверки основной идеи |
| **Масло, оставшееся в сковороде** | Взвесить сковороду до и после → вычесть из калорийности |
| **Неоднородные блюда** | Бульон отдельно от гущи: две «подготовки» с отдельными долями |
| **Многоэтапная готовка** | Добавление ингредиентов по ходу (сначала мясо ужарилось, потом добавили овощи) |
| **Тарелка из нескольких блюд** | Одна тарелка = порции из нескольких готовок, общий текст для трекера |
| **Размер бандла** | После этапа 04 — 531 КБ (169 КБ gzip): Radix + cmdk. Если станет заметно на телефоне — разбить по маршрутам (`lazy` в React Router) |
| **UI-тесты** | Testing Library / Playwright, если ручная проверка начнёт пропускать регрессии |
