# Split the Portion — продуктовая спецификация (MVP)

Статус: черновик на ревью · 2026-10-01

## 1. Цель

Веб-прототип, который пересчитывает вес еды «сырой ↔ готовый» с учётом тары и делит приготовленное на порции, чтобы порцию можно было записать в калорийный трекер **в сыром весе**.

Гипотеза, которую проверяем MVP: если у плиты за несколько секунд получить «сколько положить готового» и «сколько это в сыром для трекера», то пользователь будет взвешивать и записывать еду точнее и не станет бросать это из-за пересчётов в уме.

Что прототип **не** делает: бэкенд, аккаунты, синхронизация между устройствами, база продуктов, подсчёт калорий (это работа трекера). Данные хранятся в браузере (IndexedDB); копию можно скачать в файл и загрузить обратно — в том числе в более новую версию приложения.

Платформа: веб, сначала под телефон у плиты, потом под десктоп. Интерфейс на русском.

## 2. Глоссарий

| Термин | Определение |
|---|---|
| **Сырой вес** | Вес продукта до готовки: сухая крупа, сырое мясо. |
| **Готовый вес** | Вес продукта или блюда после готовки. |
| **Тара** | Любая посуда или ёмкость, в которой взвешивают еду: кастрюля, сковорода, миска, контейнер, ланчбокс, банка, форма для запекания. У тары есть название и вес. |
| **Вес с тарой** | То, что показывают весы, когда еда стоит на них вместе с посудой. |
| **Вес без тары** | Вес самой еды: `вес с тарой − вес тары`. Во всех расчётах используется **только вес без тары**. |
| **Готовка** | Одна варка блюда в калькуляторе: сегодняшние веса, взвешивания и порции. С этапа 15 **не хранится** — это черновик расчёта; запоминается только ввод в самом блюде (§3а). Бывает простой или составной. |
| **Простое блюдо** | Готовка из одного продукта: гречка, макароны, картофель. Вводится только продукт и его сырой вес; воду и соль не вводим. |
| **Составное блюдо** | Готовка из нескольких ингредиентов (суп, плов), в том числе на основе простого блюда. |
| **Ингредиент** | Продукт в готовке с сырым весом. Может быть помечен «не учитывать». |
| **Не учитывать** | Флаг ингредиента (вода, соль, специи). Ингредиент участвует в весе блюда, но не попадает в список для записи в трекер и не может быть базой порции. |
| **Взвешивание** | Ввод готового веса: либо сразу вес без тары, либо тара из библиотеки + вес с тарой. Первое взвешивание — после готовки. Следующие — перевзвешивания остатка. |
| **Этап** | Отрезок жизни блюда между взвешиваниями. Этап начинается с взвешивания; порции, взятые до следующего перевзвешивания, относятся к этому этапу. |
| **Блюдо** | Пресет: что готовим и что вводили в прошлый раз — продукт или ингредиенты с последним сырым весом, тара, кто ест и доли, последний готовый вес с временем. Открыл блюдо — всё подставлено, обычно вводится только готовый вес. |
| **Компания** | Пресет людей, которые едят вместе, с долями: «Ваня 70, Ксюша 60». Не путать с группой: компания — кто ест и в каких долях, у неё нет аккаунтов. |
| **Доля** | Положительное число у человека в компании; блюдо делится пропорционально долям. |
| **Порция** | Часть блюда, которую берёт человек или кладут в контейнер. Вводится **только весом еды** (без тарелки и тары): либо в готовом весе, либо в сыром весе одного из учитываемых ингредиентов. |
| **Доля порции** | `готовый вес порции / готовый вес всего блюда`. Внутри приложения любая порция сводится к доле. |
| **Коэффициент выхода k** | `готовый вес / сырой вес`. k > 1 — продукт разварился, k < 1 — ужарился или уварился. |
| **Базовый ингредиент** | Единственный учитываемый ингредиент блюда, если такой один (гречка + соль «не учитывать» → база — гречка). |
| **Сверка** | Сравнение суммы порций этапа с тем, что было доступно на этапе. |
| **Остаток** | То, что осталось в кастрюле после порций этапа. Показывается в готовом и в сыром весе. |
| **Аккаунт** | Вход по почте и паролю (можно добавить Face ID). Необязателен: без него всё хранится только на этом устройстве (§13). |
| **Группа** | Общий учёт нескольких аккаунтов: блюда (с последним расчётом), тара, компании и настройки у участников общие. У каждого аккаунта есть «Личная» группа; в неё и в другие группы зовут по коду. |
| **Группа по умолчанию** | Группа, которая открывается при запуске приложения. Выбирается в настройках; переключение на другую группу её не меняет. |
| **Синхронизация** | Обмен изменениями группы с сервером, когда есть сеть. Без сети всё работает и сохраняется на устройстве. |

Слова «нетто» и «брутто» не используем ни в интерфейсе, ни в документах, ни в коде. Вместо них «вес с тарой» и «вес без тары» (в коде `withTare` и `food`).

## 3. Ключевое решение: два вида готовки, одна модель расчёта

Вид блюда **следует из состава**: ровно один учитываемый продукт — простое блюдо, даже если к нему добавлены вода, соль или специи с отметкой «не учитывать»; два и больше учитываемых — составное. Блюдо создаётся одной общей формой («Добавить блюдо»), вверху переключатель «Простое | Составное»: он показывает, каким блюдо получится, и им же можно выбрать вид (этап 15). «Составное» добавляет строку для следующего продукта и ставит в неё курсор; если её не заполнить, блюдо сохранится простым. «Простое» у составного оставляет первый учитываемый продукт и всё «не учитывать», остальные убирает (тост «Вернуть»; до «Сохранить» ничего не записано). Вид сохраняется в блюде (`kind`) при «Создать» / «Сохранить». Расчёт общий, формулы и тесты одни и те же.

- **Простое блюдо.** Интерфейс говорит в терминах продукта: «Сухой», «k = 2,8», сверка в граммах сухого. Строки «не учитывать» в калькуляторе не показываются — на порции они не влияют.
- **Составное блюдо.** Список ингредиентов с «не учитывать». Если учитываемых ингредиентов несколько, интерфейс говорит о блюде: порции по умолчанию в готовом весе, сверка в граммах готового, результат порции — состав в сыром весе. Если учитываемый ингредиент один (гречка + соль «не учитывать»), подача как у простого.
- **Составное на основе простого.** Простое блюдо целиком переходит в составное как ингредиент: его название и сырой вес копируются (например, сваренные макароны → «Макароны по-флотски» с ингредиентом «Макароны 250 г»). Сделать это можно двумя способами: кнопкой «Составное на основе» в редакторе простого блюда (создаётся новое составное) или кнопкой «Из простого блюда» в ингредиентах составного (добавляется в существующее). Копия не связана с исходным блюдом: правка простого блюда потом составное не меняет.

## 3а. Блюдо, компания и готовка

- **Блюдо (пресет)** создаётся заранее кнопкой «Создать»: продукты с сырым весом, тара, необязательное название. Дальше оно **само запоминает то, что вводят в калькуляторе** (этап 15), без кнопки сохранения: сырой вес продуктов (рецепт меняется — это и есть «как в прошлый раз»), тару, «Кто ест» и доли (§3б), последний готовый вес. Правка в редакторе — по-прежнему по «Сохранить». Новое блюдо по умолчанию «Без тары»: не все взвешивают в посуде.
- **Компания** — пресет людей с долями: «Ваня и Ксюша» (70 : 60), «С тёщей» (70 : 60 : 60). Хранится в настройках. Там люди добавляются полем «+ Имя», а доли правятся той же полосой, что в калькуляторе (§3б), только без «На завтра»; после полосы доли хранятся в целых процентах.
- **Готовка** — одна варка блюда, считается в калькуляторе и **не хранится** (с v11): истории готовок, экрана готовки, перевзвешивания и «Разделить на N» в приложении нет. Порции людей по умолчанию — **по доле**: делят всё блюдо в соотношении долей. Любому человеку можно вписать порцию в граммах или процентах, тогда остальные делят то, что осталось; уходя из этого поля, его часть блюда запоминается как его доля в процентах.
- **Последний расчёт.** Готовый вес вводится каждый раз: сколько воды возьмут макароны, заранее неизвестно. Введённый вес запоминается в блюде вместе с тарой и временем (`cooked`) и через группу приходит другим участникам: Ксюша взвесила гречку — Ваня открывает гречку и видит «Готовый · 19:40» и свою порцию. Показывается только сегодняшний расчёт в той же таре; на следующий день поле снова пустое.

## 3б. Калькулятор

Калькулятор — главный экран (этап 15): приложение открывается на блюде, которым пользовались последним. Сверху — **полка блюд**: в начале поиск и «Все блюда» (вне прокрутки), дальше чипы блюд по последнему использованию (текущее обведено), справа «⋯» — «Изменить …», «Добавить блюдо», «Настройки». Порядок чипов не меняется, пока полка открыта: введённый вес делает блюдо последним, но чип не уезжает из-под пальца.

**Поиск** (лупа, ⌘K / Ctrl+K, «/»): сначала свои блюда — тап открывает; ниже популярные, которых ещё нет, с обычным весом («Булгур · 150 г») — тап добавляет блюдо и открывает его, тост «Отменить». Ищет по названию и продуктам, по началу слова раньше, чем по середине; «е» находит «ё».

Под полкой — плитки **«Сухой» и «Готовый»** в ряд, активная — белая коробка. Под ними одна тихая строка: тара («Кастрюля 3 л · 850 г ⌄» или «Без тары ⌄», тап открывает список), «360 г без тары · k = 2,77» или ошибка «вес меньше тары». У составного блюда продукты **свёрнуты** в плитку «Сырой» с суммой учитываемых и пометкой «не учит.: Вода 2 000 г, Соль 5 г»; тап по ней или «Продукты ⌄» показывает все продукты маленькими плитками по две в ряд («Готовый» — на всю ширину), «Свернуть ⌃» прячет. Если у учитываемого продукта нет веса, блюдо открывается развёрнутым. Ниже — компания, полоса долей и ответ для каждого человека крупными цифрами. Плитки и числа людей — обычные поля ввода (`inputmode="decimal"`): на телефоне по тапу открывается системная цифровая клавиатура, своей клавиатуры в приложении нет. Ответ пересчитывается на каждую цифру; сохранять нечего.

- Значения подставлены из блюда: последний сырой вес, тара, состав и доли. «Готовый» — сегодняшний расчёт этого блюда в той же таре с подписью «· 19:40», иначе пусто. На десктопе курсор сразу стоит в первой пустой строке, иначе в «Готовом»; на телефоне клавиатура открывается только по тапу, чтобы не закрыть ответ.
- При фокусе число в поле выделяется: первая цифра заменяет его, как в калькуляторе. Пока поле в фокусе, число показано как набрано («1240»), без фокуса — с разрядами («1 240»). Запятая и точка — одно и то же, остальное отбрасывается (`typedGrams`); целая часть — до 5 цифр, дробная — 1 цифра. Сырой вес (больше 0) и тара сразу записываются в блюдо, готовый вес — тоже, с временем.
- Enter («Далее» на клавиатуре телефона) — следующий вес; на «Готовом» и в поле человека («Готово») клавиатура закрывается, чтобы был виден ответ. ↓ и ↑ — следующее и предыдущее поле по кругу; из поля человека — к «Готовому».
- **«Кто ест»** — состав людей и их доли **у каждого блюда свои**: запоминаются у блюда до следующего изменения, другие блюда не меняются. Пока у блюда состав ни разу не меняли, берётся первая компания из настроек. Внизу списка людей — поле «+ Имя»: набрали имя, Enter — человек добавлен, поле готово для следующего (пустых строк «Без имени» нет); добавить можно кого угодно (доля — средняя по остальным), имя пишется прямо в строке, × убирает **удержанием**: пока держишь, рамка кнопки закрашивается (по умолчанию 1,5 с); отпустил раньше — ничего не происходит, короткий тап показывает «Удерживайте ×, чтобы убрать». Длительность — в настройках «Убрать человека»: Сразу / 1 с / 1,5 с / 2 с.
- **Доли** правятся ползунком; доли сохраняются в составе этого блюда. Компания при этом не меняется: ни её доли, ни название (она — шаблон, правится только в настройках).
- У каждого человека под именем — процент от всего блюда («своя · 9,9 % · 13 г сухого»).
- **Остаток**: если своих порций меньше, чем сварено, под списком «В кастрюле останется — на завтра: 267 г» (и сухой вес); если больше — красным «не хватает N г».
- **Своя порция в граммах или в процентах**: тап по числу человека — поле его своей порции (пока ничего не набрано, сегодняшнее число показано бледным, поле не меняет размер). Переключатель единицы не уводит фокус из поля. Рядом с числом всегда стоит переключатель единицы «г» / «%»: тап — та же порция в другой единице (своя порция пересчитывается), под именем — значение во второй единице. Пока не переключали, единица — как на полосе. В граммах — готовый вес, в процентах — часть блюда («мне 50 %, Ксюше 40 %»). Человек получает ровно это, остальные делят оставшееся по долям; если делить некому — остаток в кастрюле. При переключении «г ⇄ %» введённое значение пересчитывается. Пока поле своей порции активно, в состав ничего не пишется (набранное и стёртое число не оставит человеку 1 %); когда из поля ушли, части всех людей запоминаются как их доли в процентах (`lineupPercents`).
- **Сухой или готовый вид** (#24): плитки «Сухой» и «Готовый» — ещё и переключатель вида порций. Пока в фокусе «Готовый» (или после него выбрали человека), граммы у людей, на полосе долей и в своей порции — готовые, под именем — «38 г сухого». Пока в фокусе «Сухой», те же порции показаны в граммах сухого: ползунок делит сухой вес («Ваня 38 г», «Ксюша 32 г»), под именем — «100 г готового», а своя порция вводится в сухом виде: 60 г сухого — человек получает ровно столько сухого, под именем видно, сколько это готового (пока нет готового веса — только сухой). Своя порция помнит, в чём её ввели: 60 г сухого остаются 60 г сухого и после возврата в «Готовый» или нового готового веса. Вид меняется только у продукта, по которому считается k (один учитываемый продукт: простое блюдо или составное с одним учитываемым); у составного с несколькими продуктами порции всегда в готовом. Вид не запоминается: блюдо открывается в «Готовом», если «Сухой» не пуст.
- **Вернуться к долям**: «своя ×» под именем — этот человек снова делит по своей доле; «Всё в доли» — все свои порции переводятся в доли с тем же соотношением, что сейчас (Ваня 33 г и Ксюша 33 г → 50 : 50). Стёртое поле тоже возвращает человека к доле. Над списком людей — **полоса всего блюда** высотой 48 px: сегмент на человека в размере того, что он получает (имя и под ним готовые граммы; до взвешивания — процент), своя порция — пунктирный контур, то, что остаётся в кастрюле, — заштрихованный «Остаток». Так ответ виден и на маленьком экране, где список уходит под клавиатуру. Тянуть можно границы между теми, кто делит по долям. Границу между соседями можно тянуть пальцем (шаг 1 %, у каждого не меньше 1 %); под полосой всегда «− Ваня 54 % +» для выбранного (сначала — первого, тап по сегменту выбирает другого) — каждое нажатие ±1 %, разница делится между остальными пропорционально; «Поровну» — равные доли. После ползунка доли хранятся в целых процентах. Переключатель «г | %» под полосой справа, рядом с «Поровну» (одна строка с «− Ваня +»): подписи в готовых граммах (после взвешивания) или в процентах блюда; новая своя порция вводится в той же единице. **На завтра:** у правого края полосы — невидимая полоска (при наведении мышью или тапе подсвечивается: заштрихованный край и ручка); потянуть её влево — справа отсекается заштрихованная часть «На завтра» (целые проценты блюда), доли делящих уменьшаются пропорционально (см. §5). Появившаяся граница с ручкой тянется обратно; дотянули до края — отсечения нет. Отложить можно не больше, чем сейчас делят по долям, минус 1 % каждому; своя порция, введённая позже, урезает отложенное до этого предела (вернули человека к доле — отложенное снова прежнее). Ширина сегмента — ровно его доля, даже 1 %; ручки у краёв не выходят за полосу. Отложенное не запоминается: на следующий раз ничего не отложено. Пресет узнаётся по пропорции: 70 : 60 и 54 : 46 — одно и то же.
- Пресеты (компании из настроек) — один выпадающий список на всю ширину над полосой. Выбор компании заменяет состав блюда её людьми с её долями по умолчанию; выбранная компания остаётся выбранной в списке (с её названием), пока не выбрали другую, — ползунок, «+ Имя», × и имена в строках правят только состав блюда. Галочка в списке стоит у компании, пока доли совпадают с её долями; после ползунка галочки нет, и повторный выбор той же компании возвращает её доли по умолчанию. Если компания не выбрана (её удалили, или состав остался от прошлой версии), подсвечен пресет, с которым состав совпадает (те же имена и доли), иначе — «Свой состав · N». Если состав не совпадает ни с одной компанией — в конце списка пункт «Сохранить состав как компанию»: создаёт пресет «Ваня, Ксюша и Тёща» и выбирает его.
- Последний пункт списка — **«Добавить компанию»** (есть и когда компаний ещё нет): открывает диалог «Новая компания» с той же формой, что в настройках (название, полоса долей, люди, «+ Имя»; фокус в «+ Имя»). Кнопка «Добавить компанию» неактивна, пока нет ни одного человека; после неё компания записана в настройки, диалог закрыт, компания сразу выбрана и её доли подставлены. Закрыть диалог без кнопки — ничего не создаётся. 

## 4. Сценарии

> **С этапа 15** готовки не хранятся, и экрана готовки нет. Сценарии ниже описывают модель расчёта: она и её тесты не менялись. В приложении из них остались калькулятор (порции по долям, своя порция в граммах или процентах, «На завтра», остаток в кастрюле, копирование). Сверки по строкам, порции «сырой: курица», «Разделить на N» и перевзвешивания остатка в интерфейсе нет; остаток на завтра — «На завтра» и строка «В кастрюле останется» с сухим весом.

### 4.1. Один продукт (гречка)

1. **Новая готовка.** Пользователь вводит название продукта и сырой вес. Блок «Порции» сразу содержит людей из состава по умолчанию (из настроек), например «Аня» и «Борис» с пустыми полями.
2. **После готовки.** Пользователь вводит готовый вес одним из двух способов:
   - сразу вес без тары;
   - выбирает тару из библиотеки (или тут же создаёт новую) и вводит вес с тарой, а приложение показывает вес без тары.
   Приложение показывает k.
3. **Порции.** Каждый человек вводит свою порцию в сыром или в готовом весе (переключатель на строке). Рядом показан второй вес: «80 г сырого → положить 224 г готового» или «положил 250 г готового → 89 г сырого».
   - Людей в этой готовке можно добавлять и убирать, это не влияет на состав по умолчанию.
   - Кнопка «Остаток» у последнего человека подставляет ему всё нераспределённое.
   - Пока у порции не выбраны единицы, она следует за блюдом: один учитываемый ингредиент → сырой вес, составное блюдо → готовый. Так люди из состава по умолчанию, созданные раньше ингредиентов, не «застревают» на первом продукте. Выбранные вручную единицы сохраняются, даже пока поле пустое.
   - Смена единиц у заполненной порции пересчитывает число: 80 г сырого → 224 г готового (порция та же).
4. **Сверка.** Под списком: «распределено X из Y г сырого».
   - Совпадает — спокойный вид.
   - Сумма больше → красным «перебор 10 г».
   - Сумма меньше, и все строки заполнены → красным «не распределено 20 г».
   - Сумма меньше, но есть пустые строки (или людей нет вовсе) → нейтрально «осталось распределить 120 г» (это незаконченный ввод, а не ошибка).
   Порции, введённые в готовом весе, для сверки переводятся в сырой вес через долю.
5. **Остаток в кастрюле** — в готовом и в сыром весе.
6. **Копирование** — кнопка у порции копирует текст для трекера: `Гречка (сырой вес) — 89 г`.

### 4.2. Составное блюдо (суп)

1. Пользователь добавляет N ингредиентов с сырым весом. Воду, соль и специи помечает «не учитывать».
2. После готовки вводит готовый вес блюда так же, как в 4.1.
3. **Порция в готовом весе.** «Порция 395 г» → в сыром весе: курица 75, картофель 50, морковь 20, лук 15, рис 10 г. Неучитываемые ингредиенты в список не попадают.
4. **Порция от ингредиента (обратный пересчёт).** На строке порции вместо «готовый» выбирается «сырой: курица» → «хочу 100 г сырой курицы» → положить ≈ 527 г супа, а заодно видно, сколько в этой порции остальных ингредиентов.
5. **Разделить на N равных.** «8 порций» → по 395 г готового. Для каждой порции видно содержимое в сыром весе. Округление такое, чтобы сумма сошлась с итогом (см. §6).
6. Сверка, остаток и копирование работают как в 4.1, только сверка идёт в граммах готового.

### 4.3. Остаток на следующий день (перевзвешивание)

1. Порции, введённые до перевзвешивания, считаются взятыми.
2. Кнопка «Перевзвесить остаток» добавляет новое взвешивание (тоже с тарой или без; режим и тара — как в прошлом взвешивании) и начинает новый этап.
3. На новом этапе доступна доля, которая осталась после предыдущего этапа, но её готовый вес теперь новый. Приложение показывает k остатка, а новые порции считаются от нового веса.
4. Сверка нового этапа идёт против остатка, а не против всего блюда.
5. Ошибочное перевзвешивание удаляется кнопкой у последнего этапа вместе с порциями этого этапа (если они есть — после подтверждения). Переносить их на прошлый этап нельзя: порция в готовом весе там означала бы другую долю. Первое взвешивание не удаляется.
6. Порции прошлых этапов свёрнуты в строку «Этап 1 · Аня · 80 г сырого», их можно развернуть и поправить — следующие этапы пересчитаются. Сверка прошлого этапа показывается только при переборе: недораспределённое ушло в остаток.

### 4.4. Meal prep (раскладка по контейнерам)

Отдельной функции в MVP нет. Её закрывают две существующие механики:
- поровну на N контейнеров — через «Разделить на N»;
- по заданным сырым порциям — через именованные порции («Контейнер 1», «Обед вт» …).

## 5. Формулы

Обозначения: `raw_i` — сырой вес ингредиента i; `C` — учитываемые ингредиенты; `W_j` — вес без тары на взвешивании j; `A_j` — доля блюда, доступная на этапе j.

**Вес без тары**
```
food = withTare − tare        (если взвешивали с тарой)
food = введённое значение     (если ввели сразу без тары)
```

**Этапы**
```
A_0 = 1
A_{j+1} = A_j − Σ доли порций этапа j     (остаток этапа j)
```

**Доля порции на этапе j** (доля всего блюда):
```
порция в готовом весе p:                s = p / W_j × A_j
порция в сыром весе r ингредиента b:    s = r / raw_b
```

**Порция по доле** (человек из компании с долей w, SPEC §3а). Порция в процентах блюда: `s = p / 100 × A_j`. Сначала считаются порции, введённые в граммах или процентах; то, что осталось на этапе, делится между порциями по доле пропорционально весам:
```
свободно F_j = max(0, A_j − Σ s порций в граммах − K)
s = F_j × w / Σ w
```
**На завтра.** `K = keepPercent / 100` — часть всего блюда, отложенная до дележа (только на этапе 0, на перевзвешиваниях `K = 0`). Доли делящих уменьшаются пропорционально, отложенное остаётся в остатке этапа.
Доли — любые положительные числа: «1 : 1», «1,5 : 1» или сухие граммы «70 : 60» — важно только соотношение. Если свободного нет, порция по доле получает «в кастрюле ничего не осталось».

**Результат порции**
```
готовый вес = s / A_j × W_j
сырой вес ингредиента i = raw_i × s      (для i ∈ C)
```

**Коэффициент выхода k** (только для показа и проверок; в расчётах порций не участвует):
```
k_base  = W_j / (raw_base × A_j)              (если учитываемый ингредиент один)
k_dish  = W_j / (Σ_всех raw_i × A_j)          (составное блюдо; «не учитывать» тоже входят)
```
Пример 1: k = 560 / 200 = 2,8. Пример 3: k остатка = 310 / (200 × 0,6) ≈ 2,58.

**Остаток этапа j**
```
доля остатка R_j = A_j − Σ s
готовый вес остатка = R_j / A_j × W_j
сырой вес остатка по ингредиенту i = raw_i × R_j
```

**Сверка этапа j.** База сверки:
- учитываемый ингредиент один → граммы сырого веса базового ингредиента: `всего = raw_base × A_j`, `распределено = raw_base × Σ s`;
- иначе → граммы готового веса этапа: `всего = W_j`, `распределено = W_j × Σ s / A_j`.

```
diff = распределено − всего
|diff| < 0,5 г  → ok
diff > 0       → «перебор |diff| г»
diff < 0       → «не распределено |diff| г» (красным, если все строки заполнены)
```

**Кнопка «Остаток»** ставит в строку значение (в единицах строки), при котором `diff = 0`:
```
s_new = s_current + R_j;   показать, если s_new ≥ 0 и |R_j| эквивалентно ≥ 0,5 г
```

**Равные порции**: `готовый вес остатка текущего этапа / N`. Если порций ещё нет, это весь вес этапа.

**Однородность (известное ограничение).** Считаем, что блюдо однородное: в любой ложке ингредиенты в той же пропорции, что и в кастрюле. Для супа, где бульон и гуща распределены по-разному, результат приблизительный. Неоднородные блюда — в бэклоге.

## 6. Точность и округление

1. **Считаем с полной точностью** (`number`, double), промежуточных округлений нет. В хранилище лежат только введённые значения; всё остальное вычисляется.
2. **Округляем только при выводе**:
   - граммы — до целого, половина вверх (`89,5 → 90`);
   - k — до 2 знаков, лишние нули отбрасываются (`2,8`, `2,58`);
   - проценты доли — до 1 знака.
3. Вывод через `Intl.NumberFormat('ru-RU')`: десятичная запятая, разделитель тысяч — неразрывный пробел.
4. **Когда округлённые значения не сходятся с итогом:**
   - **Равные порции** («Разделить на N»): используем метод наибольшего остатка. Округляем вниз, а недостающие граммы раздаём по одному порциям с наибольшей дробной частью; при равенстве — порциям с меньшим номером. 1000 / 3 → 334, 333, 333. Сумма всегда равна округлённому итогу.
   - **Порции людей**: каждое значение округляется отдельно, а сверка идёт по точным значениям. Поэтому «224 + 336 = 560» может показаться как «223 + 337», но предупреждения не будет: ошибка округления в 1 г — не ошибка ввода. Кнопка «Остаток» ставит точное значение, и сверка сходится ровно.
   - **Разложение порции по ингредиентам**: каждый ингредиент округляется отдельно, сумма с весом порции не обязана сходиться (ингредиенты сырые, порция готовая).
   - Ингредиент, который в порции округлился до 0 г, показывается как «< 1 г» и не попадает в копируемый текст.

## 7. Ввод чисел

- Поле `type="text"` + `inputmode="decimal"`: на телефоне открывается цифровая клавиатура.
- Принимаем и запятую, и точку: `1240,5` = `1240.5`. Пробелы (в том числе неразрывные) убираем: `1 240` = `1240`.
- Допустимо: неотрицательное число, не больше одного десятичного разделителя. Разделитель в конце или в начале допустим, чтобы не ругаться посреди набора: `12,` = 12, `,5` = 0,5. Всё остальное считается ошибкой формата (`1.240,5`, `12a`, `-5`, `1e3`).
- Пустое поле — «не задано», а не 0.
- Пока поле в фокусе, ошибочный текст не стирается: показываем подсказку «Введите число, например 1240 или 12,5».
- Арифметика в поле (`1240+35`) — бэклог.

## 8. Валидация и граничные случаи

Два уровня: **ошибка** — результат не считается, поле подсвечено; **предупреждение** — результат считается, рядом жёлтая подсказка.

| Ситуация | Уровень | Поведение |
|---|---|---|
| Вес с тарой меньше или равен весу тары | ошибка | «Вес с тарой меньше веса тары — проверьте тару» |
| Готовый вес = 0 или не задан | — | Порции в сыром весе считаются, готовые значения показываются как «—»; сверка в сыром весе работает |
| Сырой вес ингредиента = 0 или не задан | ошибка у ингредиента | Ингредиент исключается из расчёта; порция от него невозможна |
| Все ингредиенты «не учитывать» | предупреждение | «Нечего записывать: все ингредиенты исключены» |
| Нет ни одного ингредиента | — | Секции «После готовки» и «Порции» неактивны |
| k_base вне [0,3; 4] или k_dish вне [0,2; 5] | предупреждение | «Необычный выход k = 6,1. Возможно, в вес попала посуда — выберите тару» (если ввод был без тары) или «Проверьте веса» |
| Сумма порций ≠ доступному | см. §5 «Сверка» | красным с разницей |
| Остаток этапа ≤ 0 или этап ещё не взвешен | — | Кнопка «Перевзвесить остаток» неактивна |
| Тару удалили из библиотеки | — | Во взвешивании хранится снимок названия и веса тары, старые расчёты не меняются |
| Тару изменили в библиотеке | — | Уже сделанные взвешивания не меняются (снимок); при новом выборе берётся новый вес |
| Ингредиент — база порции — удалён или помечен «не учитывать» | предупреждение у порции | Порция помечается «выберите, в чём вводить» и не участвует в сверке. Молча переводить её в готовый вес нельзя: это исказит цифры |
| Изменили сырые веса или готовый вес после ввода порций | — | Всё пересчитывается: храним ввод, а не результаты |
| Порции этапа 0 изменили после перевзвешивания | — | Доля остатка A_1 пересчитывается; этап 1 честно следует за этим |
| Очень маленькая доля (результат < 1 г) | — | Показываем «< 1 г» |
| Повреждённые сохранённые данные | — | Сохраняем сырую строку в резервный ключ и стартуем с пустым состоянием, показываем уведомление |

## 9. Копирование для трекера

Кнопка «Копировать» у порции кладёт в буфер обмена текст:

Один учитываемый ингредиент:
```
Гречка (сырой вес) — 89 г
```

Составное блюдо:
```
Курица (сырой вес) — 75 г
Картофель (сырой вес) — 50 г
Морковь (сырой вес) — 20 г
Лук (сырой вес) — 15 г

```

Неучитываемые ингредиенты и строки «< 1 г» не копируются. Если Clipboard API недоступен (страница по http с IP-адреса в локальной сети), показываем текст в выделяемом поле.

## 10. MVP и бэклог

### Входит в MVP

| Функция | Зачем для проверки гипотезы |
|---|---|

| Популярные блюда в настройках (~30 простых, ~20 составных) | Новый пользователь сразу видит, как устроены блюда, и не вбивает гречку и борщ руками |

## 11. Эталонные примеры (они же unit-тесты)

## 12. Решения, принятые по умолчанию (проверить на ревью)

1. Сценарий 1 — частный случай сценария 2 (одна сущность «готовка»).
2. Сверка для блюда с одним учитываемым ингредиентом идёт в граммах сырого веса, для составного — в граммах готового.
3. Предупреждение «не распределено» красным — только когда все строки порций заполнены. Пока строки пустые, «осталось распределить» показывается нейтрально.
4. Кнопка «Остаток» — только у последней строки.
5. Формат копирования: `<Название> (сырой вес) — N г`.
6. Перевзвешивание остатка (пример 3) входит в MVP последним этапом; при нехватке времени его можно отрезать без последствий для остального (доменная логика и тесты всё равно делаются в этапе 01).
7. Арифметика в поле и Wake Lock — в бэклоге с высоким приоритетом, не в MVP. PWA — этап 11 (§13).
8. Деплой не входил в MVP. Теперь приложение раздаётся с Cloudflare Workers, туда же добавляются сервер и база (этапы 12–14, [CLOUDFLARE.md](CLOUDFLARE.md)).
9. Вход необязателен; без аккаунта приложение работает как в MVP (§13).
10. В группе общее всё, что хранится; тема — настройка устройства (§13).
11. Конфликт правок решается по записи целиком: побеждает пришедшая на сервер позже (§13).

## 13. Совместный учёт и синхронизация (этапы 11–14)

Устройство — в [ARCHITECTURE §9–10](ARCHITECTURE.md#9-сервер), этапы — [11](roadmap/11-pwa.md)–[14](roadmap/14-groups.md).

### 13.1. Установка и работа без сети
- Приложение ставится на экран «Домой» iPhone (PWA) и открывается без сети: калькулятор, блюда и настройки работают как всегда.
- У приложения на экране «Домой» своё хранилище, не общее с Safari. Данные приходят туда после входа или через «Копию данных».
- Новая версия не подменяет старую молча: тост «Есть новая версия · Обновить».

### 13.2. Аккаунт
- Вход необязателен. Без аккаунта данные живут только на этом устройстве, как в MVP.
- Вход — почта и пароль; после входа можно добавить вход по Face ID. Восстановление пароля по почте — когда появятся письма (бэклог); до тех пор ссылку сброса присылает владелец приложения.
- При регистрации создаётся группа «Личная». Данные, накопленные на устройстве без входа, переезжают в неё. Если в аккаунте уже есть данные, приложение спрашивает «Перенести?».
- Выход удаляет данные групп с устройства (на сервере они остаются). Если что-то не успело уйти на сервер, сначала предупреждение.

### 13.3. Группы
- Всё, что хранится, принадлежит одной группе: блюда (с последним расчётом), тара, компании, «Кто ест» у блюд, «Убрать человека». Участники видят и правят это одинаково, отдельных прав на блюда нет.
- Тема («Оформление») — настройка устройства и в группу не входит.
- Человек может быть в нескольких группах. Открыта всегда одна. При запуске открывается **группа по умолчанию**, звёздочка в настройках. Переключение на другую группу группу по умолчанию не меняет.
- Позвать в группу — код из 8 символов или ссылка с ним. Код действует 7 дней, по нему могут вступить несколько человек, владелец может его отозвать.
- После вступления приложение предлагает открывать эту группу при запуске.
- Из «Личной» выйти нельзя. Из чужой группы — можно; владелец может убрать участника. Ушедший теряет доступ к данным группы, но они остаются у остальных; у него группа уходит с устройства при следующей синхронизации.
- Название группы меняет её владелец. У каждого своя «Личная», поэтому чужая группа в списках подписана владельцем: «Личная · vanya».
- Пример: Ваня зовёт Ксюшу в свою «Личную»; Ксюша делает её группой по умолчанию — у обоих одни блюда, тара и компания «Ваня и Ксюша»; гречку, которую взвесила Ксюша, Ваня видит у себя с её готовым весом.

### 13.4. Синхронизация и конфликты
- Правка сначала сохраняется на устройстве, потом уходит на сервер: сразу, если есть сеть, иначе — когда сеть появится и приложение открыто.
- Чужие правки приходят при открытии приложения, при возврате к нему и раз в минуту, пока оно открыто.
- **Правило конфликта:** единица — запись (блюдо с последним расчётом, тара, компания, «Кто ест» у блюда, настройки). Если одну запись правили на двух устройствах, остаётся правка, пришедшая на сервер позже. Удаление — тоже правка: удалённое блюдо вернётся, если другой человек правил его без сети и синхронизировался позже. Записи готовок, которые присылают версии до этапа 15, приложение пропускает.
- Правки разных записей друг другу не мешают: Ваня взвешивает гречку, Ксюша в это время добавляет тару — сохраняется и то и другое.
- «Загрузить из файла» в группе заменяет её данные у всех участников (с подтверждением).
- Статус виден в настройках: «Синхронизировано · 12:40», «Синхронизация…», «Нет сети — изменения сохранены на устройстве», «Войдите снова, чтобы синхронизировать», «Обновите приложение, чтобы синхронизировать».
