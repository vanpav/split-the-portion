# Split the Portion — продуктовая спецификация (MVP)

Статус: черновик на ревью · 2026-10-01

## 1. Цель

Веб-прототип, который пересчитывает вес еды «сырой ↔ готовый» с учётом тары и делит приготовленное на порции, чтобы порцию можно было записать в калорийный трекер **в сыром весе**.

Гипотеза, которую проверяем MVP: если у плиты за несколько секунд получить «сколько положить готового» и «сколько это в сыром для трекера», то пользователь будет взвешивать и записывать еду точнее и не станет бросать это из-за пересчётов в уме.

Что прототип **не** делает: бэкенд, аккаунты, синхронизация между устройствами, база продуктов, подсчёт калорий (это работа трекера). Данные хранятся в браузере (IndexedDB); копию можно скачать в файл и загрузить обратно — в том числе в более новую версию приложения.

Платформа: веб, сначала под телефон у плиты, потом под десктоп. Интерфейс на русском.

## 2. Глоссарий

| Термин | Определение |
|---|---|
| **Сырой вес** | Вес продукта до готовки: сухая крупа, сырое мясо. |
| **Готовый вес** | Вес продукта или блюда после готовки. |
| **Тара** | Любая посуда или ёмкость, в которой взвешивают еду: кастрюля, сковорода, миска, контейнер, ланчбокс, банка, форма для запекания. У тары есть название и вес. |
| **Вес с тарой** | То, что показывают весы, когда еда стоит на них вместе с посудой. |
| **Вес без тары** | Вес самой еды: `вес с тарой − вес тары`. Во всех расчётах используется **только вес без тары**. |
| **Готовка** | Одна сессия приготовления: 1..N ингредиентов, взвешивания после готовки и порции. Бывает простой или составной. |
| **Простое блюдо** | Готовка из одного продукта: гречка, макароны, картофель. Вводится только продукт и его сырой вес; воду и соль не вводим. |
| **Составное блюдо** | Готовка из нескольких ингредиентов (суп, плов), в том числе на основе простого блюда. |
| **Ингредиент** | Продукт в готовке с сырым весом. Может быть помечен «не учитывать». |
| **Не учитывать** | Флаг ингредиента (вода, соль, специи). Ингредиент участвует в весе блюда, но не попадает в список для записи в трекер и не может быть базой порции. |
| **Взвешивание** | Ввод готового веса: либо сразу вес без тары, либо тара из библиотеки + вес с тарой. Первое взвешивание — после готовки. Следующие — перевзвешивания остатка. |
| **Этап** | Отрезок жизни блюда между взвешиваниями. Этап начинается с взвешивания; порции, взятые до следующего перевзвешивания, относятся к этому этапу. |
| **Блюдо** | Рецепт: что готовим и как обычно (продукт или ингредиенты с обычным весом, тара, компания). Из блюда создаются готовки. |
| **Компания** | Пресет людей, которые едят вместе, с долями: «Ваня 70, Ксюша 60». |
| **Доля** | Положительное число у человека в компании; блюдо делится пропорционально долям. |
| **Порция** | Часть блюда, которую берёт человек или кладут в контейнер. Вводится **только весом еды** (без тарелки и тары): либо в готовом весе, либо в сыром весе одного из учитываемых ингредиентов. |
| **Доля порции** | `готовый вес порции / готовый вес всего блюда`. Внутри приложения любая порция сводится к доле. |
| **Коэффициент выхода k** | `готовый вес / сырой вес`. k > 1 — продукт разварился, k < 1 — ужарился или уварился. |
| **Базовый ингредиент** | Единственный учитываемый ингредиент блюда, если такой один (гречка + соль «не учитывать» → база — гречка). |
| **Сверка** | Сравнение суммы порций этапа с тем, что было доступно на этапе. |
| **Остаток** | То, что осталось в кастрюле после порций этапа. Показывается в готовом и в сыром весе. |

Слова «нетто» и «брутто» не используем ни в интерфейсе, ни в документах, ни в коде. Вместо них «вес с тарой» и «вес без тары» (в коде `withTare` и `food`).

## 3. Ключевое решение: два вида готовки, одна модель расчёта

Вид блюда **не выбирают, он следует из состава**: ровно один учитываемый продукт — простое блюдо, даже если к нему добавлены вода, соль или специи с отметкой «не учитывать»; два и больше учитываемых — составное. Блюдо создаётся одной общей формой («Добавить»), вверху живая плашка «Простое / Составное» показывает, каким оно получится. Вид сохраняется в блюде и готовке (`kind`) при «Создать» / «Сохранить» и определяет вкладку списка. Расчёт общий, формулы и тесты одни и те же.

- **Простое блюдо.** Интерфейс говорит в терминах продукта: «Сухой», «k = 2,8», сверка в граммах сухого. Строки «не учитывать» в калькуляторе не показываются — на порции они не влияют.
- **Составное блюдо.** Список ингредиентов с «не учитывать». Если учитываемых ингредиентов несколько, интерфейс говорит о блюде: порции по умолчанию в готовом весе, сверка в граммах готового, результат порции — состав в сыром весе. Если учитываемый ингредиент один (гречка + соль «не учитывать»), подача как у простого.
- **Составное на основе простого.** Простое блюдо целиком переходит в составное как ингредиент: его название и сырой вес копируются (например, сваренные макароны → «Макароны по-флотски» с ингредиентом «Макароны 250 г»). Сделать это можно двумя способами: кнопкой «Составное на основе» на экране простого блюда (создаётся новое составное) или кнопкой «Из простого блюда» в ингредиентах составного (добавляется в существующее). Копия не связана с исходным блюдом: правка простого блюда потом составное не меняет.

## 3а. Блюдо, компания и готовка

- **Блюдо (рецепт)** настраивается заранее и сохраняется явной кнопкой «Создать» / «Сохранить»: продукты с обычным сырым весом, тара, необязательное название. К людям блюдо не привязано: кто ест, выбирается в калькуляторе (с v6). Новое блюдо по умолчанию «Без тары»: не все взвешивают в посуде.
- **Компания** — пресет людей с долями: «Ваня и Ксюша» (70 : 60), «С тёщей» (70 : 60 : 60). Хранится в настройках.
- **Готовка** — одна варка блюда. Считается в калькуляторе (§3б); запись появляется только по «Сохранить»: она копирует ингредиенты с сегодняшним весом (рецепт не меняется), тару и компанию. Порции людей компании по умолчанию — **по доле**: делят всё блюдо в соотношении долей. Любому человеку на сегодня можно вписать порцию в граммах, тогда остальные делят то, что осталось.
- Вес после готовки вводится каждый раз: сколько воды возьмут макароны, заранее неизвестно. Он главное поле быстрого экрана.



## 3б. Калькулятор

Нажатие на блюдо в списке открывает калькулятор — как конвертер величин: сверху крупные строки «Сухой» (у составного — ингредиенты) и «Готовый», нажатие на строку делает её активной. В поле «Готовый» под подписью — тара, в которой взвешивали («Кастрюля 3 л · 850 г ⌄» или «Без тары ⌄», тап открывает список), в правом нижнем углу поля под числом мелко — «560 г без тары · k = 2,8» (без тары — только k); под полем справа — ошибка («вес меньше тары», красным). Строки «Сухой» (ингредиенты) и «Готовый» одной высоты; ниже — компания и ответ для каждого человека крупными цифрами; внизу — своя клавиатура (цифры, запятая, ⌫, C, ↓ — следующее поле, «Сохранить»). Ответ пересчитывается на каждое нажатие.

- Значения подставлены из рецепта: обычный сухой вес, тара, компания. «Готовый» — самое частое значение из сохранённых готовок этого блюда с той же тарой (при равенстве — последнее), подпись «· обычно»; не хранится отдельно, считается из истории. Пока поле не трогали, при смене тары оно пересчитывается. Активной сначала становится первая пустая строка, иначе «Готовый».
- Первое нажатие после выбора строки заменяет её значение, как в калькуляторе. Целая часть — до 5 цифр, дробная — 1 цифра.
- Калькулятор ничего не хранит. «Сохранить» (доступно после ввода готового веса) записывает готовку в историю блюда и открывает её полный экран (своя порция в граммах, перевзвешивание, «Разделить на N»).
- На десктопе своя клавиатура скрыта: цифры набираются с обычной клавиатуры, Enter или ↓ — следующее поле.
- **«Сегодня едят»** — один состав людей на все блюда, хранится до следующего изменения. Внизу списка людей — поле «+ Имя»: набрали имя, Enter — человек добавлен, поле готово для следующего (пустых строк «Без имени» нет); добавить можно кого угодно (доля — средняя по остальным), имя пишется прямо в строке, × убирает **удержанием**: пока держишь, рамка кнопки закрашивается (по умолчанию 1,5 с); отпустил раньше — ничего не происходит, короткий тап показывает «Удерживайте ×, чтобы убрать». Длительность — в настройках «Убрать человека»: Сразу / 1 с / 1,5 с / 2 с. Пока состав ни разу не меняли, берётся первая компания из настроек.
- **Доли** правятся ползунком; доли сохраняются в составе «Сегодня едят».
- У каждого человека под именем — процент от всего блюда («своя · 9,9 % · 13 г сухого»).
- **Остаток**: если своих порций меньше, чем сварено, под списком «В кастрюле останется — на завтра: 267 г» (и сухой вес); если больше — красным «не хватает N г».
- **Своя порция в граммах или в процентах**: тап по числу человека делает его целью клавиатуры (до первой клавиши число показано бледным, поле не меняет размер). Рядом с числом всегда стоит переключатель единицы «г» / «%»: тап — та же порция в другой единице (своя порция пересчитывается), под именем — значение во второй единице. Пока не переключали, единица — как на полосе. В граммах — готовый вес, в процентах — часть блюда («мне 50 %, Ксюше 40 %»). Человек получает ровно это, остальные делят оставшееся по долям; если делить некому — остаток в кастрюле. При переключении «г ⇄ %» введённое значение пересчитывается. Своя порция действует на эту готовку (сохраняется в ней), в состав не попадает.
- **Вернуться к долям**: «своя ×» под именем — этот человек снова делит по своей доле; «Всё в доли» — все свои порции переводятся в доли с тем же соотношением, что сейчас (Ваня 33 г и Ксюша 33 г → 50 : 50). C на клавиатуре тоже стирает свою порцию. Над списком людей — **полоса всего блюда**: сегмент на человека в размере того, что он получает (имя и готовые граммы; до взвешивания — процент), своя порция — пунктирный контур, то, что остаётся в кастрюле, — заштрихованный «Остаток». Так ответ виден и на маленьком экране, где список уходит под клавиатуру. Тянуть можно границы между теми, кто делит по долям. Границу между соседями можно тянуть пальцем (шаг 1 %, у каждого не меньше 1 %); под полосой всегда «− Ваня 54 % +» для выбранного (сначала — первого, тап по сегменту выбирает другого) — каждое нажатие ±1 %, разница делится между остальными пропорционально; «Поровну» — равные доли. После ползунка доли хранятся в целых процентах. Переключатель «г | %» под полосой справа, рядом с «Поровну» (одна строка с «− Ваня +»): подписи в готовых граммах (после взвешивания) или в процентах блюда; новая своя порция вводится в той же единице. **На завтра:** у правого края полосы — невидимая полоска (при наведении мышью или тапе подсвечивается: заштрихованный край и ручка); потянуть её влево — справа отсекается заштрихованная часть «На завтра» (целые проценты блюда), доли делящих уменьшаются пропорционально (см. §5). Появившаяся граница с ручкой тянется обратно; дотянули до края — отсечения нет. Отложить можно не больше, чем сейчас делят по долям, минус 1 % каждому; своя порция, введённая позже, урезает отложенное до этого предела (вернули человека к доле — отложенное снова прежнее). Ширина сегмента — ровно его доля, даже 1 %; ручки у краёв не выходят за полосу. Отложенное сохраняется в готовке (`keepPercent`). Пресет узнаётся по пропорции: 70 : 60 и 54 : 46 — одно и то же.
- Пресеты (компании из настроек) — один выпадающий список на всю ширину над полосой; выбор заменяет состав; подсвечен пресет, с которым состав совпадает (те же имена и доли). Если не совпадает ни с одним — в конце списка пункт «Сохранить состав как компанию»: создаёт пресет «Ваня, Ксюша и Тёща».

## 4. Сценарии

### 4.1. Один продукт (гречка)

1. **Новая готовка.** Пользователь вводит название продукта и сырой вес. Блок «Порции» сразу содержит людей из состава по умолчанию (из настроек), например «Аня» и «Борис» с пустыми полями.
2. **После готовки.** Пользователь вводит готовый вес одним из двух способов:
   - сразу вес без тары;
   - выбирает тару из библиотеки (или тут же создаёт новую) и вводит вес с тарой, а приложение показывает вес без тары.
   Приложение показывает k.
3. **Порции.** Каждый человек вводит свою порцию в сыром или в готовом весе (переключатель на строке). Рядом показан второй вес: «80 г сырого → положить 224 г готового» или «положил 250 г готового → 89 г сырого».
   - Людей в этой готовке можно добавлять и убирать, это не влияет на состав по умолчанию.
   - Кнопка «Остаток» у последнего человека подставляет ему всё нераспределённое.
   - Пока у порции не выбраны единицы, она следует за блюдом: один учитываемый ингредиент → сырой вес, составное блюдо → готовый. Так люди из состава по умолчанию, созданные раньше ингредиентов, не «застревают» на первом продукте. Выбранные вручную единицы сохраняются, даже пока поле пустое.
   - Смена единиц у заполненной порции пересчитывает число: 80 г сырого → 224 г готового (порция та же).
4. **Сверка.** Под списком: «распределено X из Y г сырого».
   - Совпадает — спокойный вид.
   - Сумма больше → красным «перебор 10 г».
   - Сумма меньше, и все строки заполнены → красным «не распределено 20 г».
   - Сумма меньше, но есть пустые строки (или людей нет вовсе) → нейтрально «осталось распределить 120 г» (это незаконченный ввод, а не ошибка).
   Порции, введённые в готовом весе, для сверки переводятся в сырой вес через долю.
5. **Остаток в кастрюле** — в готовом и в сыром весе.
6. **Копирование** — кнопка у порции копирует текст для трекера: `Гречка (сырой вес) — 89 г`.

### 4.2. Составное блюдо (суп)

1. Пользователь добавляет N ингредиентов с сырым весом. Воду, соль и специи помечает «не учитывать».
2. После готовки вводит готовый вес блюда так же, как в 4.1.
3. **Порция в готовом весе.** «Порция 395 г» → в сыром весе: курица 75, картофель 50, морковь 20, лук 15, рис 10 г. Неучитываемые ингредиенты в список не попадают.
4. **Порция от ингредиента (обратный пересчёт).** На строке порции вместо «готовый» выбирается «сырой: курица» → «хочу 100 г сырой курицы» → положить ≈ 527 г супа, а заодно видно, сколько в этой порции остальных ингредиентов.
5. **Разделить на N равных.** «8 порций» → по 395 г готового. Для каждой порции видно содержимое в сыром весе. Округление такое, чтобы сумма сошлась с итогом (см. §6).
6. Сверка, остаток и копирование работают как в 4.1, только сверка идёт в граммах готового.

### 4.3. Остаток на следующий день (перевзвешивание)

1. Порции, введённые до перевзвешивания, считаются взятыми.
2. Кнопка «Перевзвесить остаток» добавляет новое взвешивание (тоже с тарой или без; режим и тара — как в прошлом взвешивании) и начинает новый этап.
3. На новом этапе доступна доля, которая осталась после предыдущего этапа, но её готовый вес теперь новый. Приложение показывает k остатка, а новые порции считаются от нового веса.
4. Сверка нового этапа идёт против остатка, а не против всего блюда.
5. Ошибочное перевзвешивание удаляется кнопкой у последнего этапа вместе с порциями этого этапа (если они есть — после подтверждения). Переносить их на прошлый этап нельзя: порция в готовом весе там означала бы другую долю. Первое взвешивание не удаляется.
6. Порции прошлых этапов свёрнуты в строку «Этап 1 · Аня · 80 г сырого», их можно развернуть и поправить — следующие этапы пересчитаются. Сверка прошлого этапа показывается только при переборе: недораспределённое ушло в остаток.

### 4.4. Meal prep (раскладка по контейнерам)

Отдельной функции в MVP нет. Её закрывают две существующие механики:
- поровну на N контейнеров — через «Разделить на N»;
- по заданным сырым порциям — через именованные порции («Контейнер 1», «Обед вт» …).

## 5. Формулы

Обозначения: `raw_i` — сырой вес ингредиента i; `C` — учитываемые ингредиенты; `W_j` — вес без тары на взвешивании j; `A_j` — доля блюда, доступная на этапе j.

**Вес без тары**
```
food = withTare − tare        (если взвешивали с тарой)
food = введённое значение     (если ввели сразу без тары)
```

**Этапы**
```
A_0 = 1
A_{j+1} = A_j − Σ доли порций этапа j     (остаток этапа j)
```

**Доля порции на этапе j** (доля всего блюда):
```
порция в готовом весе p:                s = p / W_j × A_j
порция в сыром весе r ингредиента b:    s = r / raw_b
```

**Порция по доле** (человек из компании с долей w, SPEC §3а). Порция в процентах блюда: `s = p / 100 × A_j`. Сначала считаются порции, введённые в граммах или процентах; то, что осталось на этапе, делится между порциями по доле пропорционально весам:
```
свободно F_j = max(0, A_j − Σ s порций в граммах − K)
s = F_j × w / Σ w
```
**На завтра.** `K = keepPercent / 100` — часть всего блюда, отложенная до дележа (только на этапе 0, на перевзвешиваниях `K = 0`). Доли делящих уменьшаются пропорционально, отложенное остаётся в остатке этапа.
Доли — любые положительные числа: «1 : 1», «1,5 : 1» или сухие граммы «70 : 60» — важно только соотношение. Если свободного нет, порция по доле получает «в кастрюле ничего не осталось».

**Результат порции**
```
готовый вес = s / A_j × W_j
сырой вес ингредиента i = raw_i × s      (для i ∈ C)
```

**Коэффициент выхода k** (только для показа и проверок; в расчётах порций не участвует):
```
k_base  = W_j / (raw_base × A_j)              (если учитываемый ингредиент один)
k_dish  = W_j / (Σ_всех raw_i × A_j)          (составное блюдо; «не учитывать» тоже входят)
```
Пример 1: k = 560 / 200 = 2,8. Пример 3: k остатка = 310 / (200 × 0,6) ≈ 2,58.

**Остаток этапа j**
```
доля остатка R_j = A_j − Σ s
готовый вес остатка = R_j / A_j × W_j
сырой вес остатка по ингредиенту i = raw_i × R_j
```

**Сверка этапа j.** База сверки:
- учитываемый ингредиент один → граммы сырого веса базового ингредиента: `всего = raw_base × A_j`, `распределено = raw_base × Σ s`;
- иначе → граммы готового веса этапа: `всего = W_j`, `распределено = W_j × Σ s / A_j`.

```
diff = распределено − всего
|diff| < 0,5 г  → ok
diff > 0       → «перебор |diff| г»
diff < 0       → «не распределено |diff| г» (красным, если все строки заполнены)
```

**Кнопка «Остаток»** ставит в строку значение (в единицах строки), при котором `diff = 0`:
```
s_new = s_current + R_j;   показать, если s_new ≥ 0 и |R_j| эквивалентно ≥ 0,5 г
```

**Равные порции**: `готовый вес остатка текущего этапа / N`. Если порций ещё нет, это весь вес этапа.

**Однородность (известное ограничение).** Считаем, что блюдо однородное: в любой ложке ингредиенты в той же пропорции, что и в кастрюле. Для супа, где бульон и гуща распределены по-разному, результат приблизительный. Неоднородные блюда — в бэклоге.

## 6. Точность и округление

1. **Считаем с полной точностью** (`number`, double), промежуточных округлений нет. В хранилище лежат только введённые значения; всё остальное вычисляется.
2. **Округляем только при выводе**:
   - граммы — до целого, половина вверх (`89,5 → 90`);
   - k — до 2 знаков, лишние нули отбрасываются (`2,8`, `2,58`);
   - проценты доли — до 1 знака.
3. Вывод через `Intl.NumberFormat('ru-RU')`: десятичная запятая, разделитель тысяч — неразрывный пробел.
4. **Когда округлённые значения не сходятся с итогом:**
   - **Равные порции** («Разделить на N»): используем метод наибольшего остатка. Округляем вниз, а недостающие граммы раздаём по одному порциям с наибольшей дробной частью; при равенстве — порциям с меньшим номером. 1000 / 3 → 334, 333, 333. Сумма всегда равна округлённому итогу.
   - **Порции людей**: каждое значение округляется отдельно, а сверка идёт по точным значениям. Поэтому «224 + 336 = 560» может показаться как «223 + 337», но предупреждения не будет: ошибка округления в 1 г — не ошибка ввода. Кнопка «Остаток» ставит точное значение, и сверка сходится ровно.
   - **Разложение порции по ингредиентам**: каждый ингредиент округляется отдельно, сумма с весом порции не обязана сходиться (ингредиенты сырые, порция готовая).
   - Ингредиент, который в порции округлился до 0 г, показывается как «< 1 г» и не попадает в копируемый текст.

## 7. Ввод чисел

- Поле `type="text"` + `inputmode="decimal"`: на телефоне открывается цифровая клавиатура.
- Принимаем и запятую, и точку: `1240,5` = `1240.5`. Пробелы (в том числе неразрывные) убираем: `1 240` = `1240`.
- Допустимо: неотрицательное число, не больше одного десятичного разделителя. Разделитель в конце или в начале допустим, чтобы не ругаться посреди набора: `12,` = 12, `,5` = 0,5. Всё остальное считается ошибкой формата (`1.240,5`, `12a`, `-5`, `1e3`).
- Пустое поле — «не задано», а не 0.
- Пока поле в фокусе, ошибочный текст не стирается: показываем подсказку «Введите число, например 1240 или 12,5».
- Арифметика в поле (`1240+35`) — бэклог.

## 8. Валидация и граничные случаи

Два уровня: **ошибка** — результат не считается, поле подсвечено; **предупреждение** — результат считается, рядом жёлтая подсказка.

| Ситуация | Уровень | Поведение |
|---|---|---|
| Вес с тарой меньше или равен весу тары | ошибка | «Вес с тарой меньше веса тары — проверьте тару» |
| Готовый вес = 0 или не задан | — | Порции в сыром весе считаются, готовые значения показываются как «—»; сверка в сыром весе работает |
| Сырой вес ингредиента = 0 или не задан | ошибка у ингредиента | Ингредиент исключается из расчёта; порция от него невозможна |
| Все ингредиенты «не учитывать» | предупреждение | «Нечего записывать: все ингредиенты исключены» |
| Нет ни одного ингредиента | — | Секции «После готовки» и «Порции» неактивны |
| k_base вне [0,3; 4] или k_dish вне [0,2; 5] | предупреждение | «Необычный выход k = 6,1. Возможно, в вес попала посуда — выберите тару» (если ввод был без тары) или «Проверьте веса» |
| Сумма порций ≠ доступному | см. §5 «Сверка» | красным с разницей |
| Остаток этапа ≤ 0 или этап ещё не взвешен | — | Кнопка «Перевзвесить остаток» неактивна |
| Тару удалили из библиотеки | — | Во взвешивании хранится снимок названия и веса тары, старые расчёты не меняются |
| Тару изменили в библиотеке | — | Уже сделанные взвешивания не меняются (снимок); при новом выборе берётся новый вес |
| Ингредиент — база порции — удалён или помечен «не учитывать» | предупреждение у порции | Порция помечается «выберите, в чём вводить» и не участвует в сверке. Молча переводить её в готовый вес нельзя: это исказит цифры |
| Изменили сырые веса или готовый вес после ввода порций | — | Всё пересчитывается: храним ввод, а не результаты |
| Порции этапа 0 изменили после перевзвешивания | — | Доля остатка A_1 пересчитывается; этап 1 честно следует за этим |
| Очень маленькая доля (результат < 1 г) | — | Показываем «< 1 г» |
| Повреждённые сохранённые данные | — | Сохраняем сырую строку в резервный ключ и стартуем с пустым состоянием, показываем уведомление |

## 9. Копирование для трекера

Кнопка «Копировать» у порции кладёт в буфер обмена текст:

Один учитываемый ингредиент:
```
Гречка (сырой вес) — 89 г
```

Составное блюдо:
```
Курица (сырой вес) — 75 г
Картофель (сырой вес) — 50 г
Морковь (сырой вес) — 20 г
Лук (сырой вес) — 15 г
Рис (сырой вес) — 10 г
```

Неучитываемые ингредиенты и строки «< 1 г» не копируются. Если Clipboard API недоступен (страница по http с IP-адреса в локальной сети), показываем текст в выделяемом поле.

## 10. MVP и бэклог

### Входит в MVP

| Функция | Зачем для проверки гипотезы |
|---|---|
| Готовка с 1..N ингредиентами, флаг «не учитывать» | Ядро обоих сценариев |
| Простые и составные блюда раздельно (вкладки), составное на основе простого | Простое блюдо — частый случай, ему не нужен список ингредиентов |
| Готовый вес: без тары или тара + вес с тарой | Без этого у плиты не взвесить |
| Библиотека тары (CRUD + быстрый выбор + создание прямо из взвешивания) | Взвешивают в кастрюле |
| Порции с именами, ввод в сыром или в готовом весе, показ в обоих | Главный результат |
| Компании с долями в настройках, блюда-рецепты с «Создать», быстрый экран готовки | Каждый раз одни и те же люди; у плиты — только две цифры |
| Сверка суммы в обе стороны | Ошибки распределения |
| Кнопка «Остаток» у последнего | Дешёвая, частый случай «важна только моя порция» |
| Порция от ингредиента («хочу 100 г сырой курицы») | Та же механика порции, почти даром |
| Разделить на N равных | Meal prep и семейный обед |
| Остаток в кастрюле (готовый и сырой) | Нужен для этапов |
| Перевзвешивание остатка (этапы) | Эталонный пример 3, реальный сценарий «доедаем завтра» |
| Копирование текста для трекера | Финальный шаг сценария |
| Проверки и подсказки §8 | Защита от «забыл тару» |
| Удобство у плиты (базовое): цифровая клавиатура, крупные поля и кнопки (≥ 44 px), шрифт полей ≥ 16 px (чтобы iOS не зумил) | Без этого у плиты неудобно |
| Список готовок с удалением | Вернуться к вчерашнему блюду |

### Бэклог

Подробно и с приоритетами — в [`roadmap/backlog.md`](roadmap/backlog.md). Коротко: арифметика в поле, Wake Lock, PWA и офлайн, КБЖУ и личный справочник продуктов, ссылка с состоянием в URL, история и шаблоны («повторить»), средняя k по истории, планирование «хочу 300 г готового», Open Food Facts, учёт масла в сковороде, неоднородные блюда, многоэтапная готовка, тарелка из нескольких блюд.

## 11. Эталонные примеры (они же unit-тесты)

Все примеры — тесты в `src/domain/__tests__/examples.test.ts`. Сравнение с точностью до 1e-9, где результат точный; округлённые значения проверяем через функции форматирования.

### Пример 1. Гречка
Ингредиенты: гречка 200. Тара «Кастрюля» 850 г, вес с тарой 1410.

| # | Ввод | Ожидание |
|---|---|---|
| 1.0 | — | вес без тары 560; k = 2,8 |
| 1.1 | Аня 80 сырого, Борис 120 сырого | Аня 224 готового, Борис 336 готового; сверка ok; остаток 0 г готового / 0 г сырого |
| 1.2 | Аня 80, Борис 100 | распределено 180 из 200; «не распределено 20 г» |
| 1.3 | Аня 80, Борис 130 | распределено 210 из 200; «перебор 10 г» |
| 1.4 | Порция 250 готового | 89,2857… → «89 г» сырого |
| 1.5 | Аня 224 готового + Борис 120 сырого | сверка ok (готовые порции переведены в сырой вес) |
| 1.6 | Аня 80 сырого, кнопка «Остаток» у Бориса (пусто) | Борис = 120 сырого, сверка ok |
| 1.7 | Вес с тарой 800 при таре 850 | ошибка «вес с тарой меньше веса тары» |

### Пример 2. Суп
Курица 600, картофель 400, морковь 160, лук 120, рис 80, вода 2000 (не учитывать), соль 16 (не учитывать). Готовый вес без тары 3160.

| # | Ввод | Ожидание |
|---|---|---|
| 2.1 | Порция 395 готового | доля 0,125; курица 75, картофель 50, морковь 20, лук 15, рис 10; воды и соли в списке нет |
| 2.2 | Порция «сырой: курица» 100 | 526,67 → «527 г» готового |
| 2.3 | Разделить на 8 | 8 × 395, сумма 3160 |
| 2.4 | k_dish | 3160 / 3376 ≈ 0,94 |
| 2.5 | Копирование порции 2.1 | 5 строк в формате §9, без воды и соли |

### Пример 3. Остаток гречки
Готовка из примера 1, этап 0: только Аня 80 сырого.

| # | Ввод | Ожидание |
|---|---|---|
| 3.1 | — | остаток этапа 0: 336 готового = 120 сырого; доля 0,6 |
| 3.2 | Перевзвешивание: 310 без тары | k остатка = 310 / 120 ≈ 2,5833 → «2,58» |
| 3.3 | Порция 155 готового на этапе 1 | 60 сырого; остаток этапа 1: 155 готового / 60 сырого |

### Дополнительные тесты (не из ТЗ)
- Разделение 1000 / 3 → 334, 333, 333 (наибольший остаток, при равенстве выигрывает меньший индекс).
- Разбор чисел: `"1240"`, `"1240,5"`, `"1240.5"`, `" 1 240 "`, `""` → null, `"1.240,5"` / `"12a"` / `"-5"` → ошибка.
- Форматирование: `89.2857 → "89"`, `89.5 → "90"`, `2.5833 → "2,58"`, `2.8 → "2,8"`, `3160 → "3 160"` (с неразрывным пробелом).

## 12. Решения, принятые по умолчанию (проверить на ревью)

1. Сценарий 1 — частный случай сценария 2 (одна сущность «готовка»).
2. Сверка для блюда с одним учитываемым ингредиентом идёт в граммах сырого веса, для составного — в граммах готового.
3. Предупреждение «не распределено» красным — только когда все строки порций заполнены. Пока строки пустые, «осталось распределить» показывается нейтрально.
4. Кнопка «Остаток» — только у последней строки.
5. Формат копирования: `<Название> (сырой вес) — N г`.
6. Перевзвешивание остатка (пример 3) входит в MVP последним этапом; при нехватке времени его можно отрезать без последствий для остального (доменная логика и тесты всё равно делаются в этапе 01).
7. Арифметика в поле, Wake Lock, PWA — в бэклоге с высоким приоритетом, не в MVP.
8. Деплой не входит в MVP: проверяем через `pnpm dev --host` на телефоне в той же Wi-Fi-сети. Статический хостинг — первый пункт бэклога, если гипотеза подтвердится.
